# University2K26 V0.9 功能覆盖审计

> 审计日期：2026-07-24
> 审计对象：F-001～F-014、P0-00 Experience Shell、公开 Demo 与本地验证链
> 判定原则：规格存在、前端 Fixture、技术候选、真实集成、人类接受是五种不同证据，不能互相冒充

## 1. 结论先行

当前项目已经是一套**覆盖面很广、边界表达清楚、可实际试玩的 Fixture 技术候选**，但还不是“功能全部完成”的生产系统。

- 规范全集共有 **214 个稳定功能切片**。
- 其中 **123 个**已有可复核的 Fixture 技术候选证据。
- **2 个**只有部分技术候选。
- **23 个**在 F-001～F-010 内按规格明确延后。
- **66 个**属于 F-011～F-014 的已批准愿景，仍为 `pending`。
- P0-00 Experience Shell 另有五种 Demo Role Lens，用来验证跨角色首页、导航和数据边界；它是跨切片体验证据，不额外增加或虚报稳定功能完成数。

因此，对外准确说法是：

> University2K26 V0.9 已形成 F-001～F-010 的十个可玩 Fixture 纵向切片，以及学生、教师、辅导员、专业负责人和本科生院五种统一 Role Lens；所有模块仍在技术评审或愿景阶段，真实学校身份、权威数据、正式审批与生产集成尚未完成。

## 2. 证据等级

| 等级 | 含义 | 当前可使用的表述 |
|---|---|---|
| Spec | 有稳定 ID、行为、边界和验收口径 | 已定义 / 已纳入范围 |
| Role Lens Preview | 有前端角色化任务和数据边界，但无正式身份与服务端授权 | 已完成交互假设验证 |
| Fixture Technical Candidate | 有脱敏数据、代码、合同或测试，可本地复现 | 技术候选 / 本地 Demo 可玩 |

| Accepted | 产品总集成人员与必要参与者完成验收 | 当前没有模块可自行改写为 accepted |

## 4. 五角色 Experience Shell 核验

| 角色 | 当前可玩内容 | 当前不能宣称 |
|---|---|---|
| 学生 | 原 MyCareer 首页、课程阵容、F-001～F-010 模块入口 | 真实选课、成绩、支付、门禁或学校账号 |
| 教师 | Coach Studio、AI 草稿审核主行动、课程证据与非排名 Box Score | 真实课程发布、人事材料、教师评价或晋升判断 |
| 辅导员 / 学业导师 | Case 优先级、学业路径、转介、机会入口和最小披露边界 | 隐藏风险分、诊断、处分建议或代替学生选课 |
| 专业负责人 / 系主任 | 培养方案 What-if、来源冲突、课程质量与容量入口 | 自动改培养方案、自动停课或未经审批发布 |
| 本科生院 / 教务处 | 课程治理、权威镜像、政策影响包与 Evidence Pack | 查看一切个人数据、AI 正式决定或第二套权威数据库 |

共同合同：

1. 同一套视觉、Motion Token、键鼠 / 触控 / 手柄语义。
2. 同一条 `Briefing → Choose → Execute → Replay → Next Move` 责任链。
3. 每个角色都列出可见范围和禁止范围。
4. 所有身份、数字和任务均为 `Fixture`。
5. 生产版必须由学校 SSO 认证，并在服务端按角色、组织范围、用途和时限授权。

## 6. 目前最关键的缺口

### P0：接受与可复现

1. 产品总集成人员按主 Demo 路径给出 `accept / revise / reject`。
2. 第二台机器从全新 clone 运行 Web-only Fixture 路径。
3. 现场物理手柄、触屏和至少一次键盘-only 回归。
4. 冻结 90 秒路演路径，避免继续加入口导致主叙事分散。

### P1：真实智能闭环

1. 只选择一个真实输入：授权 PDF/PPT 或已准备的文本。
2. 只选择一个模型 adapter；失败时确定性回到 Fixture。
3. 模型输出必须通过现有 Schema、来源约束和教师审核门禁。
4. GX10 / 本地模型成功不等于产品接入；必须留下模型、量化、显存、吞吐、错误和回退回执。

### P1：身份与权限架构

五角色前端已经证明信息架构可行，但下一步不能继续依靠 `localStorage` 角色值扩大功能。真实版本至少需要：

- 学校 SSO/OIDC 或受控身份 adapter；
- 服务端角色 + 组织范围 + 用途 + 时限授权；
- 每次高风险读取与动作的 Replay；
- 角色变化、离职、课程结束和委托到期的撤权；
- 前端只做展示，不作为安全边界。

### P2 / Vision

F-011～F-014 已有足够详细规格。本届除非 P0 已被人类接受且仍有明确时间，不建议再开启真实支付、饮食、教师人事或学校治理实现；这些模块的合规和外部依赖远大于演示收益。

## 7. 建议冻结的展示主线

最短、最能体现项目差异的主线仍是：

1. 学生 MyCareer 看见本赛季与 SLS 240。
2. 切到教师 Coach Studio。
3. 教师在 F-001 查看来源、修改 / 通过 / 移除 AI 草稿。
4. 切回学生完成已发布互动。
5. 进入 World Exam Finals，挑战无来源的 AI 断言。
6. Replay 展示来源、人工决定、学生行动和下一步。
7. 最后打开本科生院 Role Lens，说明同一责任链可以扩展到学校治理，但明确它仍是前端 Fixture 假设。

这条路径同时覆盖 `Reverse` 立意：不是系统给学生打分并决定命运，而是把来源、选择、纠错和回放交还给学生、教师与学校责任人。

## 8. 最终判定

- **功能定义：** 完整，214 个稳定切片均有归属。
- **Demo 体验：** 已具备十个模块入口和五角色统一壳，覆盖面充足。
- **P0 技术候选：** 可复现，等待人类接受。
- **生产完整性：** 未完成，且不应在黑客松中这样宣称。
- **现在最优动作：** 停止横向扩功能，完成主路径人类验收、第二机复现、物理输入复测和一个有来源的真实模型切片。

## 9. 2026-07-25 占位清理增量

本轮没有删除诚实的外部依赖边界，而是清理了两处会让演示误解为“只有壳”的实现占位：

1. **F-001 曲线占位 → RC Model Court。** 由固定公式现场计算理想参数、C +10% 公差与 1 MΩ 输入负载六频点，显示参数、截止频率、模型版本和来源；`measured=false` 由测试锁定。真实仪器、采样率与校准回执仍是明确未知，不能冒充实测。
2. **F-009 AdventureX “尚未核对” → 参赛准备检查。** 使用仓库已有的 2026-07-23 终极指南核验快照登记提交窗口、2–4 人、GitHub、16:9 首图与小红书要求；团队最小/最大、现场时段与提交包分别得出四态解释。赛事视觉素材许可仍保持 `pending_official_confirmation`，动态 Portal 字段仍须提交前人工复核。

保留但不计为“实现占位”的内容包括：尚未选择文件、尚未开始学习、尚未检测到手柄、真实 SIS / 支付 / 门禁 / 签名归档 / Live 模型未接入，以及所有需要外部机构授权或真实硬件才能完成的状态。这些是空状态、隐私边界或生产依赖，删除会制造虚假完成。
