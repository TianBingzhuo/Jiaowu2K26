# 合规边界与红线

> 本文件精简为 1 页。详细合规手册、Claim Ledger 和提交检查清单见 [PLAYBOOK.md](../archive/superseded-8entries-20260721/PLAYBOOK.md)。

## 赛事红线（不可破坏）

1. **空白基线：** 正式开赛后创建全新代码仓库；赛前材料、历史原型和供应商样例不是本届成果，不得混入提交
2. **AI 辅助边界：** AI 可辅助部分编码，但不能让全部代码均由 AI 生成；团队成员必须能解释、调试和修改自己负责的实现
3. **可运行产品优先：** 文章、方案、PPT 和视频不能替代可运行技术产品；没有现场实现与证据的能力只能写"计划/愿景/候选"
4. **时间窗口：** 07-26 01:00 后产生的代码和内容不进入评定
5. **说法不超证据：** 对外每一句"已完成"声明必须有现场提交、运行记录和可复查数据；不得用小样本声称提升学习效果或市场成功

## IP 边界（借机制不借品牌）

- **对外品牌只用“大学2K26 / University2K26”** 及自有模块名；`jiaowu2K26`、`j2k26` 只作兼容技术标识，"NBA 2K / MyCareer / MyTEAM" 只出现在研究、类比或出处明确的说明中
- **不复制品牌资产：** 球队、球员、联盟、2K 商标、截图、音乐、字体、卡面和具体布局均不得进入参赛产品
- **机制可用，画面要原创：** "赛季、阵容、徽章、回放、管理模拟"等通用机制须以原创信息架构与视觉实现
- **2K 官方截图只作内部研究库**，不进入提交产品、路演 PPT 或公开展示
- **不声称 2K 官方合作或授权**，除非未来获得书面授权

## 数据隐私原则

- **最小采集：** 只收集功能必需的数据；不要求填写与功能无关的敏感信息（健康、家庭、财务）
- **最小披露：** 学生端不看到草稿、已移除内容或教师内部备注；跨人比较默认关闭
- **授权优先：** 课程材料、个人信息、密钥、第三方代码和媒体必须有权使用；演示优先虚构/授权样例
- **密钥安全：** 密钥只放受控环境变量/秘密管理，不回显、不提交、不在日志中出现
- **用户控制权：** 学生可隐藏类游戏措辞、关闭公开分享、撤回非必要画像、导出和删除个人数据
- **脱敏再分享：** 对外分享前必须脱敏；日志中删除不必要内容

### 数据主权与个人归档边界

- 正式成绩、学籍、财务、门禁、人事等权威归属由学校和正式制度决定；主服务可以保存获准的加密只读副本，但必须标为 replica/cache，不能自行升格为权威主记录。
- 学生可下载两类个人副本：离线可读且明确标为非权威的 HTML/JSON/CSV/PDF 包；以及由发行方签名、可选加密、可校验并可进入受控导入流程的可信包。
- **加密不等于可信：** 没有有效发行方签名、密钥链和内容哈希的包，即使有密码也不能当作学校签发记录。
- 可信包导入只进入隔离、Schema 迁移、冲突预览与人工/权威对账；不得直接覆盖学校正式数据。
- 学校可采用校内 Sovereign Node 并与主服务按目的最小化同步；门禁轨迹、完整消费流水、健康和人事原始数据默认不离开学校节点。
- 本届黑客松只允许 Fixture 展示合同，不接真实学校数据、不部署真实联邦、不发行可冒充学校证明的归档。

## 明确不做清单

| 类别 | 不做内容 |
|------|---------|
| 权威系统 | 学籍主库、财务、正式成绩写回、全校排课（P0/P1） |
| 身份与交易 | P0/P1 的生产级身份治理、真实招聘自动投递、真实支付、余额托管、门禁签发或门锁控制 |
| 客户端 | 完整 3D 校园、Unity/Unreal 客户端（P0） |
| 技术 | 自研动画引擎、真实学校教务系统对接（仅用授权样例） |
| 产品 | 多学科泛化、真正的个性化推荐算法、公开 GPA/OVR 天梯 |
| 伤害机制 | 付费买分/排名、随机分配教育机会、公开羞辱、把人商品化 |
| 声称 | 不声称提升学习效果、不声称 2K 合作、不声称覆盖所有学科 |

## 开源与第三方采用

- **开源优先且可审计：** 采用开源组件须登记上游仓库、版本/commit、许可证、哈希和用途
- **许可证保留：** 开源许可证与版权声明必须保留，传递性许可证须检查
- **第三方归属：** 字体、图标、媒体、模型和库的版本与归属须齐全并记录
- **回退就绪：** 每个关键依赖须有明确的回退方案，不能因单一依赖失败阻断 Demo

## 游戏化安全原则

- **游戏化不制造伤害：** 不付费买分、不随机分配教育机会、不公开羞辱、不把人商品化
- **状态而非身份：** "本周状态"不写成"你就是某类人"；支持到期、撤回和解释
- **不把痛苦娱乐化：** 不把挂科、疾病、Academic Probation 或心理危机当笑料或游戏事件
- **压力友好模式：** 可关闭赛事语言、倒计时动效和音效；提供普通学习模式与支持资源

## 统一美术与叙事边界

- **一个产品世界：** 学生、教师和学校端必须共用全局 Shell、Token、组件、图标、动效和资产管线；不得为“管理端方便”退回通用后台模板
- **正式语义优先：** 游戏化名称与正式名称并列；支付、门禁、健康、安全、审批、人事等页面先显示真实状态、责任方和紧急动作
- **模式平等：** 沉浸、轻量、传统和减少动效模式的信息、功能和视觉完成度一致，不用可访问性换取次等体验
- **原创而非仿制：** 统一风格来自自有 Art Bible，不通过复制 2K 的画面、卡面、字体、音乐或具体布局获得

## General Balance 与支付边界

1. **统一视图不等于混账：** General Cash、Policy Balance、External Rails、Module Cap 和非货币 Entitlement 分账、分规则、分状态展示。
2. **外部通道不是余额：** 支付宝、微信支付、云闪付、银行卡和 Stripe 只作为交易通道；不读取、保存或汇总用户完整外部账户余额。
3. **不存敏感卡数据：** 不保存完整卡号、CVV、支付密码或第三方账户口令；只使用合规服务提供的令牌化引用和最少交易字段。
4. **政策资金透明：** 补助的来源、允许场景、期限、优先级、拒绝原因和申诉入口必须可见；不能静默挪用或伪装成自由现金。
5. **Module Cap 属于自我预算：** 软限额优先；硬限额只约束用户主动选择的可选消费，不能阻断紧急健康、安全或学校规定的强制流程。
6. **不做金融产品：** 不提供贷款、利息、授信、投资、套现、代收代付网络或交易排名；AI 不得独立冻结、拒付或判断欺诈。
7. **本届边界：** 黑客松内即使选择该 Slice，也只允许 fixture / sandbox 和明确标注的模拟交易，不接真实资金。

## Campus Pass 与实体安全边界

- 体验层只镜像和解释身份/权益；正式签发、撤销、应急解锁和安全处置由校园权威系统执行。
- 不把静态二维码截图当安全凭证，不在客户端暴露门锁密钥、主密钥或可重放令牌。
- 通行日志按最小目的和保留期处理；不用于推荐、公开排名、考勤推断或精细移动画像。
- 无手机、设备没电、残障陪同和紧急情况必须有人工/实体凭证回退。
- 黑客松内不连接真实门锁、真实门禁账户或校园生产网络。

## 饮食、健康、教师与学校决策边界

- 食材、过敏原和营养信息只展示官方/餐饮方确认来源；未知时明确未知，不由模型猜测，不提供疾病诊断或治疗方案。
- 课程、方向、科研、机会和饮食建议必须列出理由、来源、未知、替代项和正式下一步，用户可关闭、纠错或拒绝。
- AI 不自动作出录取、成绩、资助、医疗、纪律、聘任、薪酬、绩效或晋升决定，也不输出此类“成功概率”。
- 学校运营建议默认使用聚合、匿名或最小化数据；不得建立个人消费榜、通行榜、健康榜、教师 OVR 或学生价值排名。
- What-if 结果必须显示假设、数据版本、受影响群体、权衡与责任人，不得伪装成已发布政策。
