# jiaowu2K26 技术栈组合手册

> 状态：赛前决策规则，不是实现方案或已构建架构。正式开赛后才创建代码、数据、环境和 Demo。
> 项目层级：`jiaowu2K26` 是总项目；本手册主要围绕其首个 P0 模块“智课工坊”筛选现场组合。

## 一、不可被技术选型改变的核心闭环

无论现场拿到什么资源，P0 都只验证一条链：

1. 导入一份真实且有权使用的课程材料；
2. 找到一个带页码、时间戳或 source ID 的来源片段；
3. 生成一个结构化学习对象；
4. 教师查看证据并修改、通过或移除；
5. 只有通过的对象才进入学生端；
6. 学生完成一次互动，系统给出可解释反馈。

任何技术如果不能直接加强这六步之一，就不能因为“有赞助赛道”进入 P0。

## 二、组合上限

一套现场主路径最多包含：

- 1 个主模型 / 推理供应商；
- 1 个编排方式：自有小链路或 Dify，二选一；
- 1 个主数据与审核层；
- 1 个有辨识度的交互端；
- 1 条明确回退。

机器人、XR、区块链、实时音视频不是默认组件。它们必须先证明解决了一个真实用户问题。

## 三、推荐组合

### A. 软件优先可信闭环

| 层 | 首选 | 回退 |
|---|---|---|
| 材料理解 / 生成 | 现场已开通且测试通过的赞助模型；阶跃星辰优先首测 | 另一已确认 API；仍失败则只演示人工录入的结构化对象并明确说明 |
| 编排 | 自有最小业务链 | Dify Cloud，仅在账号和模型接入已通时 |
| 数据 / 审核 | 现场创建的本地结构化存储与审核页 | 飞书多维表格 |
| 学生端 | 简单 Web 页面 | 同机展示 |
| 部署 | 本机 / 局域网 | AWS 或 Zeabur 等现场确认的云端资源 |

适用：绝大多数团队；先证明产品核心。  
不要做：同时接 MiniMax、PPIO、StepFun、Dify 和 CAMEL 来“自动择优”。

### B. 可追溯端侧课堂

组合：A + D-Robotics。

D-Robotics 只负责一个边界明确的事件，例如手势、目标、语音片段或按钮输入，并输出 source ID、时间戳和置信信息。课程生成和教师审核仍由软件主链负责。

启用条件：

- 精确 RDK SKU 和外设已确认；
- 前 2 小时设备可连接；
- 前 6 小时一个官方感知基线已转换为智课工坊 source event；
- 设备失败时，软件闭环仍能独立演示。

### C. 低功耗语音 / IoT 教室端

组合：A + TuyaOpen；需要更高语音质量时再加科大讯飞，但不要同时引入 TEN 全家桶。

适合：

- 教师用语音创建带时间戳的课堂事件；
- 学生用按钮 / 麦克风作答；
- 灯光、扬声器或屏幕反馈；
- 教室终端与审核后台分离。

启用条件：板卡、麦克风 / 扬声器、AI 授权和网络在前 2 小时全部可用。

### D. 小而醒目的物理反馈

组合：A + Nothing Glyph Matrix。

Glyph 只显示少量状态，例如“待审核、已通过、学生答对、需要帮助”，不承载课程逻辑。它的价值是低集成面、现场一眼可见。

启用条件：手机型号与 SDK 支持表匹配，Android 构建和设备安装在前 4 小时跑通。

### E. 空间学习

在 PICO 与 Vision Pro 中二选一：

| 路线 | 适合团队 | 核心技术 | 风险 |
|---|---|---|---|
| PICO | 已熟悉 Unity / Unreal / OpenXR | PICO SDK、OpenXR、空间交互 | 资产、引擎和设备调试 |
| Vision Pro | 已熟悉 Swift / Apple 平台 | SwiftUI、RealityKit、Vision、Foundation Models | Xcode、系统与开发者权限 |

空间层只呈现一个已审核学习对象和一次交互；材料解析、审核和发布仍在 A 中完成。若前 6 小时空间最小交互未通，立即回到 Web。

### F. 实时远程口语课堂

组合：A + TEN Framework + Agora，只适用于“远程实时对话”本身是核心问题。

启用条件：

- Agora 与所有语音服务凭证已开通；
- 端到端延迟、回声和断线重连在现场网络下合格；
- 团队有一名成员专门负责 RTC；
- 本地录音 / 文本交互可作为回退。

只做展位本地互动时，不采用这套组合。

### G. 可验证学习凭证

组合：A + Injective。

只有当多个学校、平台或认证方确实不互信，并且用户需要公开验证的凭证时，才把最小证明上链。课程原文、学生个人信息和详细审核记录不直接上链。

启用条件：

- 赛道要求和测试网资源已明确；
- 隐私、撤销和密钥丢失方案清楚；
- 评委能在 90 秒内理解“为什么普通数据库不够”；
- 合约失败不影响教学主闭环。

## 四、明确禁止的堆叠

| 不推荐组合 | 原因 |
|---|---|
| Dify + CAMEL + TEN | 三层编排与 Agent 生命周期，调试面远大于产品价值 |
| StepFun + MiniMax + PPIO 同时作为主模型 | Key、限流、数据条款和输出差异成倍增加 |
| Injective + XION | 两套账户、链与合约，不符合最小闭环 |
| PICO + Vision Pro | 两套引擎 / 平台，内容与交互无法在 72 小时内同时打磨 |
| D-Robotics + AGILE-X + Seeed 机械臂 | 设备、ROS、驱动、供电与安全风险叠加 |
| TEN + Agora + 科大讯飞 + 多家 ASR / TTS | 音频链路难以定位故障，账号依赖过多 |
| ModelScope LoRA 训练 + 本地大模型迁移 | 数据、显存、许可证和训练时间挤压核心功能 |
| 秒哒 + 多个云 CDE + 多个 AI 编程工具 | 工程所有权和可迁移性变差，团队工作流频繁切换 |

## 五、AI 快速匹配规则

收到现场资源清单后，按以下顺序处理：

1. 先过滤赛事合规、资源可得、许可证、前 6 小时可启动和可回退；
2. 再按核心问题匹配能力；
3. 同类只留一个 Primary 和一个 Fallback；
4. 精确 SKU / Credit 未知的候选不打分；
5. 从高风险技术中最多选择一个作为 P1；
6. 所有最终结论都附官方证据和核验时间。

### 输入问题

AI 在推荐前至少需要这些输入：

- 团队成员人数与每人的熟悉技术；
- 最想证明的一个用户价值；
- 现场精确设备、配件、账号和 Credit；
- 网络、电脑系统、内存 / GPU 与借用时段；
- 独立赛道的必选能力；
- 可使用课程材料的权利；
- 期望的 90 秒演示路径；
- 可接受的回退形式。

### 输出格式

每次推荐必须包含：

- Primary：只列一套主链；
- Secondary：写清启用条件；
- Fallback：写清触发条件和对评委的说明；
- Rejected for P0：说明为什么不选；
- First 6 Hours：给出五项验证；
- Unknowns：列出仍需官方回答的事项。

## 六、开赛后前 6 小时决策闸门

### 0–1 小时：规则与资源

1. 保存当届最终规则与开赛时间证据；
2. 拍照记录精确设备 SKU、配件、系统和借用条款；
3. 确认 API Credit、账号、限流与数据条款；
4. 正式创建现场仓库和空白基线；
5. 选择 A 作为默认主链。

### 1–2 小时：最小连通

1. 一个模型请求成功并返回可校验结构；
2. 一条 source record 能保存；
3. 一个审核状态能改变；
4. 一个学生端对象能读取“已通过”内容；
5. 硬件候选只做通电、连接和官方最小示例。

### 2–4 小时：真实数据

1. 用一份有权使用的真实课件；
2. 生成一个对象并回指页码 / 时间戳；
3. 做一次修改、通过和移除；
4. 记录延迟、错误和成本；
5. 确认软件闭环无需硬件也可运行。

### 4–6 小时：去留

- 通过最小验证的一个硬件 / 交互层进入 Secondary；
- 未通过的立即移出 P0，不继续“再试半天”；
- 建立断网、API 限流和设备不可用回退；
- 冻结 P0 组合，之后新增想法只进入 P1 清单。

## 七、现阶段默认判断

在精确权益公布前：

- 默认 Primary 候选：组合 A；
- 最值得优先验证的模型：阶跃星辰；
- 最值得优先验证的数据协作层：飞书，但本地数据合同必须能独立工作；
- 最值得优先验证的硬件层：D-Robotics 或 TuyaOpen，按精确套件二选一；
- 最低成本的演示增强：Nothing Glyph；
- 最需克制的路线：双 XR、多机器人、多 Agent、多链与临时模型训练。

这些只是选型优先级，不是已完成架构，也不会在赛前转化为可运行工程。
