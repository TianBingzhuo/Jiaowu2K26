# F 模块逐项交付门禁

> **适用范围：** F-001～F-014
> **当前授权：** 产品总集成人员允许 Codex 在本机按“一个模块、一个可演示闭环”的顺序持续实现和技术验收；该授权不等于代替人类完成最终接受、合并或比赛声明。

## 1. 为什么按模块闭环

大学2K26 的功能很多，但现场版本不能变成一组彼此不相连的页面。每次只把一个 F 模块推进到可演示候选：它必须拥有正式入口、真实状态变化、失败与回退、Replay 证据和统一美术，然后才进入下一个模块。

P0 功能点是进入下一模块的最低门槛。P1/P2/Vision 仍保留在规格中，但除非当前 Demo 依赖，不得为了“看起来完整”阻塞 P0。

## 2. 状态词典

| 状态 | 含义 | 允许说法 |
|---|---|---|
| `pending` | 只有规格，尚未实现 | “计划 / 候选” |
| `in_progress` | 已有代码，但门禁未齐 | “正在实现” |
| `technical_review` | 本机自动化与浏览器 QA 已通过，等待产品总集成人员检查 | “技术候选已就绪” |
| `accepted` | 产品总集成人员明确接受，证据已归档 | “本届已实现” |
| `deferred` | 主动裁剪到后续阶段，原因已记录 | “路线图” |

Codex 可以把模块推进到 `technical_review`；只有产品总集成人员可以决定 `accepted`、合并 PR 和创建 `p0-xx-accepted` Tag。

## 3. 每个功能点的验收卡

每个 `Fxxx-yy` 至少回答以下问题：

1. **用户任务：** 谁在什么情境下完成什么决定或动作？
2. **输入与来源：** 输入来自 Fixture、缓存还是 Live？权利、版本和定位是否可见？
3. **正式状态变化：** 动作改了什么数据？是否有 revision、操作者和时间？
4. **成功路径：** 可以从入口走到结果、Replay 和 Next Move。
5. **失败路径：** 至少一个错误可复现，错误不播放成功反馈。
6. **回退路径：** 网络、模型、数据库或硬件不可用时仍诚实可用。
7. **权威边界：** AI/规则只能交草稿；高风险写入保留人工批准或正式系统确认。
8. **多输入等价：** 键盘、鼠标、触屏、手柄语义一致；读屏与减少动效不丢信息。
9. **人因边界：** 首读含义、压力、公平、隐私、退出/申诉与误用风险已记录；AI 走查不冒充真人证据。
10. **可验证证据：** 单元/契约测试、构建、浏览器走查、桌面与手机截图均可重放。

## 4. 模块交付门禁

一个 F 模块只有同时满足以下条件，才能从 `in_progress` 进入 `technical_review`：

- P0 功能点逐项有 `pass / partial / pending / deferred` 结论；`partial` 和 `pending` 不被隐藏。
- 主闭环能在两分钟内从入口完成，且不会依赖未声明的人工操作。
- 正常、失败、回退各至少一条路径实际运行。
- UI、API、持久化和 Replay 对同一状态使用同一含义。
- 格式化、静态检查、单元/契约测试和生产构建全过。
- 1440 桌面和 390 手机布局通过浏览器检查；核心键盘焦点可见，Reduced Motion 有等价结果。
- 新增素材有来源、许可证/生成方式、用途、文件名、哈希和替代方案；禁止借用 NBA 2K 受保护资产。
- 模块 `STATUS.md`、项目 Manifest、CHANGELOG 和演示路径与代码一致。
- 截图、日志和测试只使用虚构/授权数据，不含密钥、真实学号或未授权课程材料。

## 5. 美术交付规则

- 全部模块复用 `engineering/DESIGN-SYSTEM.md` 与 `engineering/MOTION-SYSTEM.md`，不得独立换肤。
- 先复用已登记的品牌、场景、课程和图标资产；缺少关键视觉时再生成新素材。
- AI 生成素材必须按目标槽位尺寸、构图、光线和密度定制，并登记为 `generated_asset`；不得用占位框、Emoji、ASCII 或临时 SVG 冒充成品。
- 动画遵循 `Briefing → Choose → Execute → Replay → Next Move`，只强化状态与因果，不用无限循环遮住任务。

1. **F-001 智课工坊：** 来源 → 教师审核 → 发布 → NAN 互动 → Replay。
2. **F-002 MyCareer：** 赛季身份、课程阵容、任务与 Next Move，把 F-001 放回大学生涯。
