# 下载与本地缓存策略

> 目标是让现场准备更快，同时避免下载错误板型资源、违反赛事边界或把供应商样例误当成参赛成果。

## 三档策略

### A. 赛前研究可保留

- 官方公开规格、规则、许可证和文档链接；
- 用户主动提供的资料；
- 对公开资料的摘要、哈希和核验日期；
- 只读的下载计划与版本选择依据。

目前采用“链接 + 摘要 + 哈希”方式，不批量镜像网站。

### B. 精确资源确认后再下载

- 对应 SKU 的产品手册、配件手册和系统说明；
- 与现场系统版本匹配的离线文档；
- 明确允许提前保存的安装器或工具。

下载前必须知道用途、版本、许可证、大小和保存位置。

### C. 正式开赛后下载或生成

- RDK OS、固件、SDK 和 Docker 镜像；
- Model Zoo、NodeHub 项目和示例代码；
- HBM、ONNX、PyTorch 等模型产物；
- 数据集、校准集、现场输入和生成结果；
- 可运行依赖、构建缓存和演示资源。

若主办方书面允许其中某项赛前下载，再把该项从 C 调整到 B，并保存答复证据。

## 不自动下载

- 非官方镜像或来源不明的压缩包；
- 需要绕过登录、付费、地域或访问控制的资源；
- 未阅读许可证的模型和数据集；
- 不匹配精确板型的系统镜像、驱动或 HBM；
- 会执行安装脚本、改变系统或启动后台服务的文件；
- 包含密钥、账号令牌或个人数据的内容。

## 下载记录字段

每个实际下载项必须记录：

- `id`、供应商和资源名称；
- 官方 URL 与最终 URL；
- 版本、发布日期和适用 SKU；
- 文件名、字节数和 SHA-256；
- 许可证或使用条款；
- 下载日期、执行人和目的；
- 赛事合规依据；
- 是否为 P0、P1、Fallback 或仅供研究。
