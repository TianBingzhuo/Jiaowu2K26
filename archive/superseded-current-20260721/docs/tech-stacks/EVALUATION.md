# 技术栈统一评估标准

> 项目层级：`jiaowu2K26` 是总项目；“智课工坊”是当前首个 P0 模块。
> 目标不是挑“参数最大”的技术，而是挑能在规则内、72 小时内，把 jiaowu2K26 的智课工坊核心闭环做得最可信的组合。

## 一、硬门槛

以下任一项为 `fail`，该技术栈不得进入 P0 主路径；信息不足时标记 `unknown`，先补证据。

| 门槛 | 必须回答的问题 | 通过标准 |
|---|---|---|
| 赛事合规 | 是否允许使用该资源、官方示例和赛前资料？ | 有官方规则或主办方明确答复 |
| 资源可得 | 现场是否确实能领取或使用？ | 型号、数量、时间和方式已确认 |
| 最小可启动 | 团队能否在前 6 小时点亮并跑通最小路径？ | 有明确操作链和现场支持 |
| 许可证与数据 | 代码、模型、素材和数据是否允许使用与展示？ | 许可证和权利边界清楚 |
| 核心适配 | 是否直接支持至少一个 P0 核心步骤？ | 不是只为“蹭赛道”而接入 |
| 可回退 | 硬件、网络或 API 失败后是否仍能演示主价值？ | 有不伪装实时结果的回退 |

硬门槛状态只使用：`pass`、`fail`、`unknown`、`not_applicable`。

## 二、100 分评分表

每个维度先给 0–5 分，再按权重换算。所有分数必须附证据和置信度。

| 维度 | 权重 | 5 分含义 |
|---|---:|---|
| 产品核心匹配 | 20 | 直接强化“来源可追溯、教师审核、学生互动”主线 |
| 72 小时可行性 | 20 | 团队能快速点亮，集成链短，故障面可控 |
| 资源与支持确定性 | 15 | 型号、数量、配件、账号、Credit 和技术支持都明确 |
| 生态与集成成熟度 | 15 | 官方文档、SDK、样例、社区和调试工具完整 |
| 现场演示辨识度 | 10 | 评委能在 90 秒内看到独特且真实的价值 |
| 离线与稳定性 | 8 | 关键链路断网可用，启动和恢复路径清楚 |
| 隐私、许可证与安全 | 7 | 数据最小化、权利清楚、危险动作可控 |
| 可迁移性与锁定风险 | 5 | 数据合同和业务逻辑可迁移，供应商绑定可接受 |
| **合计** | **100** |  |

换算公式：`维度得分 = 原始分（0–5）× 权重 ÷ 5`。

## 三、置信度

| 级别 | 条件 |
|---|---|
| High | 官方当届规则、精确 SKU、现场清单或已确认技术答复 |
| Medium | 官方产品文档或当前维护的官方仓库，但现场条件仍有未知 |
| Low | 二手介绍、往届经验、营销描述或未经验证推断 |

没有证据的项目不得用 0 分代替未知；应保留 `null` 或 `unknown`，并进入问题清单。

## 四、与 jiaowu2K26 P0 的功能映射

每个技术栈至少映射到下列一项，并说明是 P0、P1 还是回退：

| 项目步骤 | 可能需要的能力 |
|---|---|
| 材料采集 | 摄像头、麦克风、PPT/文档解析、时间戳 |
| 来源对齐 | OCR、ASR、视觉事件、source ID、帧或页码定位 |
| 辅助生成 | LLM/VLM、结构化输出、schema 校验 |
| 教师审核 | Web/UI、编辑、通过、移除、审计记录 |
| 学生互动 | 显示、语音、手势、按钮、灯光或机器人动作 |
| 运行保障 | 离线模式、缓存、日志、监控、故障回退 |

## 六、反偏差规则

- 不因赞助奖金额高就强行改变产品问题；
- 不因硬件参数高就默认集成更容易；
- 不把供应商营销指标当成现场实测；
- 不把往届硬件、旧版本 SDK 或其他板型模型当成本届事实；
- 不把“能运行官方 Demo”当成“完成了我们的产品”；
- 横向比较必须使用同一时间点、同一评分口径和同一 P0 定义。
