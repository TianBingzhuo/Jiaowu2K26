# NBA 2K × maimai 全功能机制对标与安全转译

> **文档性质：** 赛前产品研究，不是参赛实现，也不构成任何品牌合作或授权声明。  
> **研究口径：** 以 NBA 2K25 官方模式报告为主，必要时标注 2K24 / 历代机制；以 maimai DX 国际版官方玩法页为主。这里覆盖可辨认的产品系统、模式与交互机制，不虚称枚举每一名球员、动画、卡片、曲目或版本活动。  
> **核心结论：** NBA 2K 提供“大学生涯的宏观经营语法”，maimai 提供“单次学习的微观节拍与同伴协作语法”。两者都只能借通用机制，不能复制名称、画面、音乐、字体、角色、截图、卡面或具体布局。

## 0. 统一判断框架

每个机制只允许进入下列一种状态：

| 状态 | 含义 |
|---|---|
| **采用** | 教育价值和风险边界都明确，可进入既有模块规格 |
| **改造采用** | 保留反馈循环，删除付费、羞辱、操纵、随机资格或权威冒充 |
| **延后** | 有价值但不进入 P0；只能在 P0 稳定后与其他支线竞争 |
| **拒绝** | 即使实现容易也不进入产品 |

所有拟采用机制还要通过“**Vought Test / 沃特测试**”：如果一个权力极强、唯 KPI 论的机构拿到它，能否用来监控、操纵、羞辱、商品化或不公平筛选学生？如果答案是“能”，则必须改成私密、可解释、可关闭、可申诉、无权威效力的形态；改不掉就拒绝。

## 1. 两套游戏各自负责什么

```text
NBA 2K：身份 → 构筑 → 阵容 → 赛季 → 关键比赛 → 生涯历史
                    ↓
jiaowu2K26：目标 → 课程/机会 → 学期 → 关键任务 → 证据回放 → 四至八赛季档案

maimai：选曲 → 选难度 → 节拍输入 → 即时判定 → 重试/协作 → 解锁地图
                    ↓
jiaowu2K26：选目标 → 选支架 → 微交互 → 即时解释 → Replay/Buddy → 学习路径
```

- **2K 是宏观系统层：** F-002、F-004、F-006、F-008、F-009、F-013、F-014。
- **maimai 是微观交互层：** F-001、F-005、F-006、F-007、F-008。
- **共享安全底座：** 来源、审核、Replay、同意、可访问性、可携带与统一 Design System。

## 4. 归并后的三个实验合同

这些不是新模块，也不增加 214 个稳定功能切片；它们只是跨模块验收与研究 ID。

### EXP-CASE-09 · Builder & Test Court

- **来源：** MyPLAYER Builder、Build Tester、MyCOURT、Salary Cap、Breakout。
- **最小形态：** 用户输入目标和约束 → 系统生成 A/B/C 方案 → 在沙盒中预演 → 展示依赖、冲突、未知和相对当前方案的 diff。
- **边界：** 不写回教务、不预测“成功概率”、不把模板当命令。
- **映射：** F-002、F-004、F-006、F-009；P1/P2，P0 无新增实现。

### EXP-CASE-10 · Learning Rhythm & Buddy Chart

- **来源：** maimai 的多谱面难度、TAP/HOLD/SLIDE/TOUCH、即时判定、Freedom Mode、BUDDY Chart、宴会場。
- **最小形态：** 同一知识目标具有至少两种支架；每次输入即时回指证据；支持低压力自由练习和一个真正需要互补协作的双人任务。
- **边界：** 不用操作精度替代知识判断；无连胜/断签惩罚；键盘、触屏、读屏信息等价。
- **映射：** F-001、F-005、F-006、F-007、F-008；P1/P2，P0 仅保留兼容接口，不扩功能。

### EXP-CASE-11 · Season Spotlight & Mentorship

- **来源：** 2K 系列 All-Star / awards / The W Mentorship / Community Goals，以及 maimai Invitation Play / CIRCLE。
- **最小形态：** 一次可选的学期高光周，包含技能挑战、跨年级导师、社区共同目标、作品展示和多元贡献奖；提名依据和退出方式可见。
- **边界：** 不按 GPA 选“全明星”，不设人气总榜，不把困难同学当反差素材，不让导师身份取得隐性权力。
- **映射：** F-002、F-005、F-006、F-007、F-008、F-009、F-013；P2/Vision，P0 无影响。

## 6. 优先级纪律

### P0 不因本研究扩张

P0 仍然只有 F-001 完整证据闭环与 F-002 轻外壳。游戏研究在 P0 只贡献三类**设计合同**，不新增玩法：

1. 统一 Shell 与正式/游戏化双标签。
2. 来源并置、即时解释、Replay 与无障碍等价。
3. 为 Builder、多难度谱面和跨端同步保留稳定接口，但不提前实现。

### P1 只能选一条

若 P0 稳定，优先顺序为：

1. **World Exam Finals + Learning Rhythm 的最小单人版**：Demo 最有记忆点且复用 F-001。
2. **Roster Lab + Builder/Test Court**：技术辨识度最高，但求解器风险更大。
3. **Opportunity Market**：边界清楚、独立性强。

Buddy、All-Star、CIRCLE、3D 城市、游戏引擎和真实跨校联邦均不抢占 P0/P1。
