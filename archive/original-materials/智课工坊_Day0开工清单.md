# 智课工坊 Day0 开工清单

**用途**：AdventureX 2026 现场开工前的执行口径  
**目标**：把现有调研资料压缩成团队可以直接开发、演示、路演的作战包  
**版本**：v1.0  
**日期**：2026-06-23

---

## 一、现场约束与判断

AdventureX 2026 官方 FAQ 显示，活动将在 2026 年 7 月 22-26 日于杭州举行，形式是五天内从 0 到 1 做出功能产品并在最终 Demo Day 展示。官方说明强调 hackathon 的重点不是做完美产品，而是在有限时间里把想法变成可运行作品。

参考来源：
- AdventureX FAQ: https://faq.adventure-x.org/en/advx/01-activities/
- AdventureX 官网: https://adventure-x.org/en

因此，智课工坊现场目标不是证明“完整教育平台可商业化”，而是证明一件事：

> 教师给出课程材料后，系统能快速生成一节可观看、可互动、可被教师审核的大学动画课。

---

## 二、北极星 Demo

### 90 秒核心演示

1. 教师端展示一段课程材料已经上传完成。
2. 系统生成结构化教学脚本，脚本包含知识点、旁白、动画指令、出题点。
3. 教师在审核界面修改一句话，点击确认。
4. 学生端播放 30-60 秒动画片段。
5. 到时间点弹出一道 AI 题目，答题后显示解析。
6. 收束一句：同一份材料还能生成复习指南或编程练习。

### 成功标准

| 维度 | 最低标准 | 理想标准 |
|------|----------|----------|
| 可运行性 | P0 主路径本地稳定跑通 | 断网也能演示预加载数据 |
| 可理解性 | 评委 30 秒内理解产品价值 | 评委能复述“课程材料 -> 教师审核 -> 互动短课 -> 复习卡” |
| 可展示性 | 至少 1 个完整课时片段 | 3 个知识点片段 + 1 个编程题 |
| 可追问性 | 能解释技术架构和 fallback | 能展示证据链、API/Schema/数据流 |

## 三、MVP 分层

### P0 必做：闭环成立

| 模块 | 交付物 | 现场判断 |
|------|--------|----------|
| 材料输入 | 音频/PPT上传入口，或预加载课程材料 | 可以 live 上传，也可以半 live |
| 脚本生成 | 结构化脚本 JSON | 必须可展示 AI 改写结果 |
| 教师审核 | 脚本预览 + 可编辑 + 确认按钮 | 必须体现人在回路中 |
| 证据模式 | 生成内容可追溯到 PPT/口播来源 | 必须能解释 AI 不是凭空生成 |
| 动画播放器 | 根据脚本播放模板动画/图文动画 | 可用 Lottie、Framer Motion 或 HTML 动效 |
| 出题互动 | 时间点弹题 + 提交 + 解析 | 必须是核心差异化 |
| Demo fallback | 预生成脚本、题目、播放器数据、录屏 | 必须准备 |

### P1 加分：增强记忆点

| 模块 | 交付物 | 截止规则 |
|------|--------|----------|
| TTS 配音 | Edge-TTS 或预生成音频 | Day3 晚仍不稳定则改预录 |
| 复习指南 | Markdown/HTML 预览 | P0 稳定后再接入 |
| Monaco 代码练习 | 代码编辑器 + 预置测试结果 | 只做编程课场景 |
| 课程指标 | 生成耗时、题目数量、成本估算 | 可用静态数据 |

### P2 只做概念展示

| 模块 | 展示方式 | 不做内容 |
|------|----------|----------|
| Computer Use 教学 | 10-20 秒预录视频或 PPT 示意 | 不做实时 agent 操作 |
| BGM 选曲 | 播放器里放一首免版税音频 | 不做自动匹配 |
| 大学配置 | 静态品牌皮肤或截图 | 不做权限/后台 |
| 数据仪表盘 | PPT Appendix | 不做真实分析后台 |

### 明确不做

- 自研动画引擎
- 完整登录/注册/权限系统
- 支付系统
- 真实学校教务系统对接
- 多学科泛化
- 真正的个性化推荐算法

## 四、推荐 Demo 课程

**课程**：《数据结构与算法》  
**知识点**：二叉搜索树 BST  
**选择理由**：
- 适合动画展示：树结构、插入、查找都可视化。
- 适合实时出题：选择题、判断题、代码题都自然。
- 适合 Monaco 加分：可写 Python/JS 插入函数。
- 专业深度足够，能证明不是 K12 简化版。

### 建议准备 3 个片段

| 片段 | 主题 | 展示形式 | 出题点 |
|------|------|----------|--------|
| L1 | 什么是二叉搜索树 | 树节点逐步出现 | 判断左右子树规则 |
| L2 | 如何查找一个值 | 高亮搜索路径 | 给定目标值选路径 |
| L3 | 如何插入新节点 | 动态插入节点 | 编写 insert 函数 |

## 五、接口契约先行

现场第一件事不是先做 UI，而是锁定前后端共享 JSON。P0 所有模块围绕 `PlayerData` 消费即可。

### Script JSON

```json
{
  "lesson_id": "bst-001",
  "title": "二叉搜索树的查找与插入",
  "subject": "computer_science",
  "duration_seconds": 360,
  "scenes": [
    {
      "id": "s1",
      "start": 0,
      "duration": 45,
      "narration": "二叉搜索树有一个核心规则：左子树更小，右子树更大。",
      "visual": {
        "template": "tree_build",
        "props": {
          "nodes": [8, 3, 10],
          "highlight": [8]
        }
      },
      "quiz_trigger": null
    }
  ]
}
```

### Quiz JSON

```json
{
  "quiz_id": "q1",
  "scene_id": "s2",
  "trigger_second": 95,
  "type": "single_choice",
  "question": "在二叉搜索树中，值 5 应该出现在根节点 8 的哪一侧？",
  "options": ["左侧", "右侧", "根节点", "无法判断"],
  "answer_index": 0,
  "explanation": "5 小于 8，因此查找或插入时先进入左子树。"
}
```

### Player Data

```json
{
  "lesson_id": "bst-001",
  "title": "二叉搜索树的查找与插入",
  "audio_url": "/demo/audio/bst-001.mp3",
  "scenes": [],
  "quizzes": [],
  "code_playground": {
    "enabled": true,
    "language": "python",
    "initial_code": "def insert(root, val):\n    pass",
    "expected_output": "inorder traversal is sorted"
  }
}
```

### Evidence Bundle

```json
{
  "lesson_id": "bst-001",
  "evidence_items": [],
  "generated_objects": [],
  "exam_signal_links": []
}
```

P0 不需要复杂知识图谱，只需要支持“生成对象 -> 证据来源 -> 老师审核动作”。

## 六、团队分工

假设 4 人团队：

| 角色 | Day1 主责 | Day2 主责 | Day3-5 主责 |
|------|-----------|-----------|-------------|
| P1 全栈/后端 | FastAPI、文件上传、mock API | 脚本/出题/播放器数据 API | 集成、部署、fallback |
| P2 前端 | 页面骨架、教师端、学生端路由 | 脚本审核、播放器 | 交互打磨、截图、录屏 |
| P3 AI | prompt、ASR、脚本 JSON | 出题 JSON、质量评估 | 成本/耗时数据、Q&A 技术口径 |
| P4 产品/设计 | Demo 课程素材、PPT/视觉 | 动画模板、话术 | 路演、展台、用户反馈收集 |

### 协作规则

- 每个模块只认一个 owner。
- 每天晚上必须合并一次可演示版本。
- 任何功能如果 2 小时内无法集成，就改为 mock 数据。
- 所有等待型 AI 调用都必须有“预加载数据”按钮或后门。

## 七、五天执行节奏

### Day1：把壳跑起来

必须完成：
- 前端三页：教师上传、教师审核、学生播放器。
- 后端三个接口：上传、生成脚本、获取播放器数据。
- Demo 课程素材进入仓库或本地约定目录。
- 第一版 `Script JSON` 和 `Quiz JSON` 锁定。

停止规则：
- 如果 live ASR 不稳，直接使用预转写文本。
- 如果 PPT 解析不稳，直接使用提取后的 markdown。

### Day2：把核心闭环打通

必须完成：
- 课程材料 -> 脚本 JSON。
- 脚本 JSON -> 教师审核页。
- 证据包 JSON -> 教师审核页侧边栏。
- 脚本 JSON -> 播放器动画数据。
- 脚本 JSON -> 题目 JSON。

停止规则：
- 如果动画效果不够好，改成“可视化图文动画”，不要继续追精致角色动画。

### Day3：把演示路径变顺

必须完成：
- 90 秒演示路径完整走通。
- 答题弹层和解析稳定。
- 至少一份完整 fallback 数据。
- 开始录第一版 Demo 视频。

停止规则：
- P0 未稳定前，不接入 Computer Use 和 BGM。

### Day4：打磨与证据

必须完成：
- Demo 视频 1.0。
- PPT 插入真实截图。
- 生成耗时、脚本质量、API 成本的实测/预估数据。
- 完成 Q&A 分工。

### Day5：路演与展台

必须完成：
- 路演 2 次计时彩排。
- 本地 demo、录屏 demo、截图 fallback 三套都可用。
- 展台可循环播放 30-60 秒产品片段。

## 九、路演口径

### 一句话定位

智课工坊让大学教师上传课程材料后，快速生成可审核、可互动的动画课程。

### 三句话价值

1. 对教师：把课程制作从“从零做视频”变成“审核 AI 生成脚本”。
2. 对学生：把 60 分钟录播变成 5-8 分钟知识点动画和即时练习。
3. 对学校：把课程数字化从平台建设推进到内容生产效率。

### 不要主动说

- “完全达到洋葱学院质量”
- “没有竞争对手”
- “能覆盖所有学科”
- “已经验证完商业模式”

### 主动承认

- 动画质量初期不追人工精制，只追可理解、可互动、可规模化。
- 教师审核是必要环节，不把 AI 生成当成直接发布。
- 数据合规和版权是后续产品化前的重点。

## 十、最终出场 Checklist

- [ ] P0 主路径可在本地完整跑通。
- [ ] 断网时可用预加载数据演示。
- [ ] Demo 视频小于 3 分钟，本地和云端各一份。
- [ ] PPT 有 3 张以上真实产品截图。
- [ ] 架构图中文显示正常，或已改为英文。
- [ ] Q&A 有明确主答人。
- [ ] 所有数据点能说清来源或标注为估算。
- [ ] 素材版权安全，无真实学生隐私。
