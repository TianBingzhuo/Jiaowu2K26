# jiaowu2K26 · AdventureX 现场开工指南

> 状态说明：本文件只是一份现场执行清单。赛前没有可运行项目、构建产物或已完成 Demo。
> 规则快照：已于 2026-07-21 对照[公开终极指南](docs/ADVENTUREX-2026-GUIDE.md)核验；主题与赛道细则仍须等 07-22 晚开幕式公布。

## 赛前只做什么

- 熟悉问题、用户与已有材料；
- 确认团队分工、设备、账号和网络预案；
- 整理公开可用的课程样例与数据边界；
- 把 72 小时任务拆成可领取的小卡片；
- 不创建功能代码，不生成可运行原型，不把目标能力写成已完成。

## 官方开赛后第一小时

1. 等待 07-22 晚开幕式结束、官方宣布 Hacking 开始，再确认当届规则与允许使用的赛前材料；
2. 全员用 10 分钟核对 [项目总览](docs/PROJECT.md)、[决策日志](docs/DECISIONS.md) 和 [合规边界](docs/COMPLIANCE.md)，确认 jiaowu2K26 是总项目、智课工坊是 P0；
3. 记录且只能选择 1 个主题，并把准备进入的 1–6 个赛道逐条映射到产品证据；
4. 确认正式队伍为 2–4 人，每人只在一个团队；
5. 新建现场代码仓库，记录创建时间和首个空白基线提交；
6. 把团队成员、任务板、环境版本和开源依赖登记写入现场日志；
7. 从最小数据合同、一条空白页面和一个审核状态迁移开始实现；
8. 每个功能保留提交记录、测试证据和完成时间；团队成员必须能解释和修改代码，不能让全部代码均由 AI 生成。

## 72 小时建议顺序

1. 先打通“材料 → 来源片段 → 一个生成对象”；
2. 再做“教师查看证据 → 修改/通过/移除”；
3. 然后做“仅把审核通过内容发布给学生”；
4. 用一个轻量 MyCareer 赛季/课程外壳说明它属于 jiaowu2K26，不同时做完所有模块；
5. 最后补异常状态、离线兜底、用户测试与路演材料。

详细拆分见 [docs/BUILD.md](docs/BUILD.md)，目标演示脚本见 [docs/features/SMARTCOURSE.md](docs/features/SMARTCOURSE.md)。两者都是现场计划，不是当前实现说明。

## 合规留痕

- 保存官方开赛时间、仓库创建时间与首个提交；
- 每日保留简短工作日志和关键功能提交；
- 明确区分赛前材料、现场代码与现场生成内容；
- 为每个实际引入的开源组件记录上游、精确版本、许可证、用途和修改；
- 对外只说现场实际完成并验证过的能力；
- 若规则解释有疑义，先向主办方确认，再继续实现。

## 收工前检查

- 项目能在一台干净设备上按 README 启动；
- 演示路径与异常回退均经过现场测试；
- 密钥、个人信息和无权公开的课程材料未进入仓库；
- 路演稿、截图和数字不超出现场实现与实测证据；
- 提交记录足以说明项目是在 AdventureX 期间完成的。
