# Campus Life Hub · 功能规格

> **模块编号：** F-008 · **优先级：** Vision  
> **基线日期：** 2026-07-22  
> **状态：** 长期愿景规格，不是完成声明  
> **稳定 ID：** 沿用 2026-07-21 八入口版本；既有 ID 不得改义或复用。

## 1. 使命

把散落在网站、公众号、群聊和线下窗口的校园活动、社团、服务与协作入口组织成可搜索、可行动的枢纽，让学生找到正式入口，而不是让体验层冒充办事结果。

## 2. 功能清单

| ID | 功能 | 具体行为与验收口径 | 阶段 |
|---|---|---|---|
| F008-01 | 服务目录 | 教务、图书馆、健康、心理、无障碍、住宿、财务等以官方来源和办理边界分类 | Vision |

## 3. 最小数据合同

| 对象 | 最低字段 |
|---|---|
| `CampusResource` | 类型、提供方、正式入口、办理边界、更新时间、验证状态、`source_ids` |
| `CampusEvent` | 主办方、时间、地点、成本、资格、截止、无障碍信息、过期状态 |
| `SavedJourney` | 用户保存步骤、正式链接、个人备注、镜像状态、最后核对时间 |
| `ProfilePreference` | 用户主动选择的兴趣、阶段、关闭状态、推荐用途和到期时间 |
| `TeamListing` | 角色、时间、协作方式、最小公开字段、双方确认状态 |
| `EscalationRoute` | 问题类型、学校/当地正式渠道、适用范围、更新时间、紧急标记 |

## 4. 不变量

1. 体验层不冒充审批、报名、缴费、医疗或危机处理结果。
2. 每条服务和活动信息都显示提供方、更新时间、验证状态和纠错入口。
3. 个性化画像可关闭；MyCOURT 默认私密，组队双方确认后才扩大披露。
4. 安全、健康和危机问题优先跳转正式渠道，不用游戏化流程拖延求助。
5. 紧急通知和营销通知严格分开，不以签到或参与度定义学生价值。
6. 完整 3D 校园不进入当前 MVP；先证明二维信息枢纽的真实价值。

## 5. 验收标准

- [ ] 服务目录和活动目录均显示来源、时效、办理边界及过期状态。
- [ ] 统一搜索支持目标、时间、地点、形式和可访问性筛选，条件可清空。
- [ ] 个性化首页可关闭画像并解释推荐原因。
- [ ] 日历整合只保存和提示冲突，不自动报名或取消。
- [ ] 二维地图提供位置、路径和无障碍信息。
- [ ] MyCOURT 默认私密且可导出。
- [ ] 组队双方确认后才交换更多资料，并提供举报渠道。
- [ ] 服务进度明确标为镜像，不冒充正式审批。
- [ ] 紧急升级能直接显示经核对的正式渠道。
- [ ] 通知类别、频率和免打扰可由用户控制。
- [ ] 数据不可用或过期时不猜测、不静默展示。

## 6. 依赖与边界

- 上游：F-002 生涯上下文、F-003 课程与学期基础数据。
- University OS 扩展：F-010 提供身份/通行与设备权益，F-011 提供分账与模块预算，F-012 提供菜单和饮食建议；F-008 只负责把它们编排进校园生活入口，不复制账务、门禁或餐饮领域数据。
- 共享：X-02 来源、X-05 同意、X-06 搜索、X-07 通知、X-08 可访问性。
- 本模块为 Vision，不进入本届 P0/P1 排程；Unity/Unreal 只能作为后期可丢弃外壳评估。
