# 智课工坊 / SmartCourse Studio · 功能规格

> **模块编号：** F-001 · **优先级：** P0
> **基线日期：** 2026-07-21
> **状态：** 待验证规格，不是完成声明

---

## 1. 使命

把教师有权使用的 PPT、讲义、录音或转写，转成可定位来源、可由教师审核、只在批准后发布的互动学习单元。

## 2. 核心原则

1. **AI 必须 Show your work：** 每个生成片段都能回到来源、规则、版本和人的决定
2. **人保留决定权：** 教师决定发布，学生决定披露
3. **小闭环先于功能展柜：** P0 只证明"来源 → 审核 → 发布 → 互动 → 回放"
4. **每项能力可回退：** 网络、模型、数据库或硬件失效时仍可诚实演示核心价值

## 4. P0 User Stories（12 个）

### US-01：上传课程材料
**角色：** 教师 · **优先级：** P0
**需求：** 我希望上传课程录音、PPT 或视频文件，系统记录文件元信息和权利状态
**AC：**
- [ ] 支持 MP3/WAV/MP4/PPTX/PDF 格式，≤50MB
- [ ] 上传后显示进度条，完成后状态变为对应解析状态
- [ ] 记录文件哈希（sha256）、上传者、权利状态
- [ ] 不支持的格式给出明确错误提示
- [ ] 无权利说明的文件标记为 `unauthorized`，不得进入生成流程

### US-02：系统提取材料内容
**角色：** 教师 · **优先级：** P0
**需求：** 系统自动将上传的材料提取为结构化的来源片段
**AC：**
- [ ] 音频/视频 → ASR 转写为带时间戳的文本
- [ ] PPT → 每页提取标题、文本、图片、备注
- [ ] PDF → 提取文本和页码定位
- [ ] 每个来源片段获得唯一 `source_id` 和定位器（页码/时间戳/文本跨度）
- [ ] 解析失败时显示原因和可重试步骤

### US-03：AI 生成教学草稿
**角色：** 教师 · **优先级：** P0
**需求：** 点击"生成"后，系统基于提取的来源片段生成教学草稿
**AC：**
- [ ] 生成脚本（scene + narration）、测验题（quiz）、知识点和复习卡
- [ ] 每个生成对象附带至少 1 个 `source_id` 指向来源片段
- [ ] 无法从材料中支持的断言标记"证据不足"
- [ ] 生成模式标记为 `model`（AI）、`rule`（规则）或 `fixture`（预置）
- [ ] 模型超时/不可用时自动切换 fixture 模式并显式提示

### US-04：查看证据来源
**角色：** 教师 · **优先级：** P0
**需求：** 在审核页，我能看到每个 AI 生成片段对应的原始材料证据
**AC：**
- [ ] 点击"查看证据"按钮打开侧边栏证据抽屉
- [ ] 显示原文引用（quote）、来源类型、置信度
- [ ] 证据项按与当前生成对象的关联度排序
- [ ] 考试信号（S/A/B 级）以 Badge 形式显示
- [ ] 至少 3 个生成对象能正确展示对应来源

### US-05：教师审核——编辑
**角色：** 教师 · **优先级：** P0
**需求：** 我可以修改 AI 生成的任何片段
**AC：**
- [ ] 编辑后保存修改前后的差异到 ReviewEvent
- [ ] 修改不改变来源关联（除非教师手动解除）
- [ ] 编辑器支持富文本（至少段落、加粗、列表）
- [ ] 编辑状态仍为 `draft`，需额外点击"通过"才变为 `approved`

### US-06：教师审核——通过
**角色：** 教师 · **优先级：** P0
**需求：** 我对满意的片段点击"通过"
**AC：**
- [ ] 状态变为 `approved`，记录操作者和时间戳
- [ ] 通过后该对象可进入发布流程
- [ ] 通过动作产生 ReviewEvent（追加式）

### US-07：教师审核——移除
**角色：** 教师 · **优先级：** P0
**需求：** 我对不满意的片段点击"移除"
**AC：**
- [ ] 状态变为 `removed`，需填写原因
- [ ] 已移除对象不进入发布，学生端不可见
- [ ] 移除原因保存到 ReviewEvent
- [ ] 移除是终态（不可恢复），但保留审计记录

### US-08：发布已审核版本
**角色：** 教师 · **优先级：** P0
**需求：** 我点击"发布"将已通过的片段发布给学生
**AC：**
- [ ] 只有 `approved` 状态的对象被包含在发布版本中
- [ ] 发布形成不可变版本（PublishedVersion），记录版本号、教师、时间和范围
- [ ] 来源仍有效（未过期/未撤回）才可发布
- [ ] 发布后学生可访问内容

### US-09：学生学习互动
**角色：** 学生 · **优先级：** P0
**需求：** 我观看已发布的学习内容并完成互动
**AC：**
- [ ] 按场景顺序展示教学内容
- [ ] 到达触发时间点时弹出测验题
- [ ] 提交答案后显示解析和来源 Badge
- [ ] 每次互动产生 StudentInteraction 记录
- [ ] 学生端只显示轻量 Badge（"老师重点" / "来自PPT" / "来自口播"）

### US-10：学习回放（Replay）
**角色：** 学生 / 教师 · **优先级：** P0
**需求：** 查看学习过程的时间线回放
**AC：**
- [ ] 按时间顺序展示所有互动事件
- [ ] 显示每道题的作答、是否正确、用时
- [ ] 教师可查看（不展示其他学生敏感数据）
- [ ] 回放数据包含来源和教师修改信息

### US-11：Box Score（学习统计）
**角色：** 学生 · **优先级：** P0
**需求：** 查看本次学习的统计摘要
**AC：**
- [ ] 显示完成率、正确率、用时分布
- [ ] 薄弱知识点高亮
- [ ] 不展示班级排名或其他学生数据
- [ ] 统计数字可回到具体题目和来源

### US-12：Demo 回退模式
**角色：** 教师 / 演示者 · **优先级：** P0
**需求：** 当 AI 模型不可用时，使用预生成数据完整演示
**AC：**
- [ ] 提供"加载预生成结果"按钮（Demo Mode）
- [ ] 加载 `demo-pack/golden/` 下的 fixture 数据
- [ ] 状态机仍然可用（教师可审核/发布 fixture 数据）
- [ ] 明确标注当前为 Demo 模式，不伪装实时成功

## 5. 审核状态机（完整状态转换）

```
                    ┌────────────────────────────────────────────┐
                    │              Review Cycle                   │
                    │  ┌──── edit ────┐                          │
                    │  │              ▼                          │
material ──→ draft ──→ review ──→ approved ──→ published        │
                         │                              │        │
                         ├─→ removed（终态）              │        │
                         │                              ▼        │
                         └─→ rejected（可重新生成）    withdrawn  │
                                                        ↑        │
                                          withdraw 事件┘        │
                    └────────────────────────────────────────────┘

状态说明：
- draft: 初始生成，等待教师审核
- review: 教师正在查看/编辑
- approved: 教师已通过，可发布
- removed: 教师已移除，不发布，终态
- rejected: 教师已拒绝，可触发重新生成
- published: 已发布给学生（PublishedVersion 层面）
- withdrawn: 已撤回（材料更新或教师主动撤回）
```

**转换规则：**
| 当前状态 | 允许动作 | 目标状态 | 条件 |
|---------|---------|---------|------|
| draft | 开始审核 | review | 至少 1 个来源片段有效 |
| review | 编辑 | review | 保存差异到 ReviewEvent |
| review | 通过 | approved | 来源仍有效 |
| review | 移除 | removed | 需填写原因 |
| review | 拒绝 | rejected | 可触发重新生成 |
| approved | 发布 | published | 创建 PublishedVersion |
| published | 撤回 | withdrawn | 材料失效或教师主动 |

## 6. EvidenceItem 数据结构详解

### 6.1 核心字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 唯一标识，格式 `ev-xxx` |
| `source_asset_id` | string | 指向来源资产（转写稿/PPT 提取结果） |
| `source_ref` | string | 精确定位，如 `bst_transcript.md#L9` 或 `bst_slide_extract.json#slides[1]` |
| `source_type` | enum | `transcript` / `slide` / `handout` |
| `quote` | string | 原文引用（直接摘录） |
| `summary` | string | 证据摘要（一句话说明这条证据的意义） |
| `confidence` | number | 0-1，表示 AI 对该证据关联的置信度 |
| `teacher_action` | enum | `accept` / `edit` / `reject` / `null`（教师对该证据的操作） |

### 6.2 与生成对象的关系

每个 `GeneratedObject` 通过 `evidence_ids` 数组关联多个 `EvidenceItem`。例如：
- 一个脚本场景可能关联 2 个证据（口播 + PPT）
- 一道测验题可能关联 1 个证据（口播中的某个知识点）
- 一张复习卡可能关联多个证据（老师口头重点 + PPT 复杂度对比）

### 6.3 考试信号

`ExamSignalLink` 将证据与生成对象通过优先级链接：
- **S 级：** 老师明确口头强调的核心内容
- **A 级：** PPT 标题级概念或关键定义
- **B 级：** 补充说明或扩展知识

## 7. 核心对象与不变量

### 数据流链路

```
Material → SourceFragment → GeneratedObject → ReviewEvent → PublishedVersion → StudentInteraction
```

### 不变量（系统必须始终保证）

1. 一个对象至少关联一个仍可定位的来源，才能进入审核
2. 只有已通过（`approved`）版本能发布
3. 审核与发布事件只追加，不覆盖历史
4. 模型的自报置信度不能代替证据强弱
5. 学生端不得看到草稿、已移除内容或教师内部备注
6. 无权利说明的材料不得进入生成流程
7. 演示 fixture 和实时结果不可共用同一状态标签

## 8. P0 验收场景

### 端到端验收路径

用一份授权材料完成以下完整链路：

1. **上传材料** → 记录 Material 对象（权利状态、哈希、上传者）
2. **提取来源** → 生成至少 3 个 SourceFragment（定位器有效）
3. **生成草稿** → AI 或 fixture 生成至少 5 个 GeneratedObject，每个附带 EvidenceItem
4. **教师审核** → 教师查看来源并执行 edit / approve / remove 各至少 1 次
5. **发布** → 只发布已通过对象，形成 PublishedVersion
6. **学生互动** → 学生完成至少 1 道测验，产生 StudentInteraction
7. **回放** → 查看 Replay 时间线和 Box Score 统计

### 必须覆盖的状态

- 正常路径：上传 → 生成 → 审核 → 发布 → 学习
- 失败状态：解析失败、生成超时、来源失效
- 回退路径：fixture 模式完整走通审核状态机
- 审计完整：每次审核操作都有 ReviewEvent 追加

## 12. “01 基座”兼容性验收合同

F-001 是第一条完整纵向切片，因此会把它采用的合同变成后续模块的兼容基线；这不增加 F001-xx 功能编号，也不扩张 P0 用户功能。

1. **平台无关领域链：** `Material → SourceFragment → GeneratedObject → ReviewEvent → PublishedVersion → StudentInteraction` 不包含 WinUI、DOM、文件路径或任一移动平台对象。
2. **版本化边界：** 对外对象都带 Schema 版本；同一主版本新增字段必须可忽略，未知枚举显示 `unknown` 并阻止高风险自动动作。
3. **统一 Fixture：** Windows 浏览器、PWA 与未来客户端消费同一 Fixture 和错误示例；不能为了某个平台另造字段含义。
4. **Capability Adapter：** 文件选择、相机、通知、离线存储和分享只通过能力接口调用；能力缺失时显示等价替代路径。
5. **状态与证据同义：** draft / approved / removed / published、EvidenceItem、Replay 与错误原因跨平台不得改义或遗漏。
6. **可访问性等价：** 游戏化交互、动效与未来 maimai 式节拍输入必须同时提供键盘、触屏、读屏和减少动效的信息等价方式。
7. **个人可携带预留：** 从第一版对象起保留稳定 ID、发行方、来源、版本、时间与权威级别，使未来 X-11 双归档无需重写历史记录。
8. **兼容性变更门禁：** 任何 Schema、状态机、身份、审计或导出字段变更必须由全队评审，附迁移、旧版读取、回退和 Golden Fixture 影响；不得在功能 PR 中顺手破坏。

完整跨平台、可信归档和学校主权联邦规则见 [`engineering/ARCHITECTURE.md`](../../engineering/ARCHITECTURE.md#01-基座兼容性宪章)。
