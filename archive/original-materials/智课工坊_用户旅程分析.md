# 智课工坊 SmartCourse Studio — 用户旅程分析

**项目代号**：SCS  
**文档版本**：v1.1  
**日期**：2026-06-24  
**分析范围**：教师旅程（内容生产者）9 阶段 + 学生旅程（内容消费者）9 阶段 + 学生 Onboarding 21天引导旅程

---

## 一、旅程总览

智课工坊是一个双角色平台：教师作为内容生产者将课程材料转化为动画课程，学生作为内容消费者观看动画并通过AI出题检验学习效果。两条旅程通过"数据飞轮"形成正反馈循环。

### 旅程概览

| 维度 | 教师旅程 | 学生旅程 |
|------|---------|---------|
| 角色定位 | 内容生产者 | 内容消费者 |
| 阶段数量 | 9 阶段 | 9 阶段 + 21天 Onboarding 覆盖层 |
| 情绪峰值 | 查看学生数据（极佳） | 完成课程（极佳） |
| 情绪低谷 | 预览动画课（困惑） | 答题+看解析（困惑） |
| Dropout Risk | 上传材料、审核修改、预览动画课 | 浏览课程列表、答题+看解析、Day1-2注册后沉默 |
| Moment of Truth | 审核修改（脚本质量决定去留） | 开始观看动画（动画质量决定去留） |
| Delight | 查看学生数据 | 完成课程 |

## 二、教师旅程详细分析

**Persona**：李老师 / 计算机科学副教授，45岁，教授《数据结构与算法》，每学期200+学生  
**JTBD**：把现有课程录音/课件，在不增加额外工作量的前提下，快速转化为5-8分钟的动画互动课程

### 2.1 阶段详细数据

#### 阶段 1：发现平台（Discovery）

| 维度 | 内容 |
|------|------|
| 情绪 | 🙂 满意 / Pain Level: 2 |
| 用户目标 | 找到一个能将课程录音转化为动画课的工具 |
| 触点 | 搜索引擎/学术社区、同行推荐/教学研讨会、平台 Landing Page、微信公众号 |
| 痛点 | 不知道有这类平台存在；难以相信AI能生成高质量的大学水平动画；与传统MOOC的差异化不清晰 |
| 机会点 | 与高校教务处合作定向推广；Landing Page 用 Before/After 对比展示效果；提供免费试用（1门课程免费生成） |

#### 阶段 2：注册（Sign Up）

| 维度 | 内容 |
|------|------|
| 情绪 | 🙂 满意 / Pain Level: 2 |
| 用户目标 | 快速注册并进入课程创建流程 |
| 触点 | 注册页面、邮箱/手机验证码、新手引导流程 |
| 痛点 | 注册表单字段过多影响转化；教育邮箱验证流程可能受阻；缺少社交账号一键登录 |
| 机会点 | 支持微信/钉钉 SSO 一键登录；教育邮箱验证后置；3步内完成注册 |

#### 阶段 3：上传材料（Upload）⚠️ Dropout Risk

| 维度 | 内容 |
|------|------|
| 情绪 | 😕 困惑 / Pain Level: 4 |
| 用户目标 | 将课程录音、PPT等材料顺利上传到平台 |
| 触点 | 材料上传页面、文件选择器、上传进度条、格式/大小提示 |
| 用户心声 | "我的录音文件格式支持吗？""上传速度太慢了，PPT有50MB呢""上传完了然后呢？" |
| 痛点 | 大文件上传耗时长（PPT常超50MB）；不支持某些录音格式；上传后无反馈；ASR转写专业术语可能不准确 |
| 机会点 | 实时进度条+预估剩余时间；支持断点续传和批量上传；上传完成推送通知；提供学科专业术语词典增强ASR |

**分析**：这是教师旅程的第一个体验断点。上传是教师"投入时间"的开始，如果等待时间过长或反馈不足，教师会质疑平台的专业度并可能放弃。建议：优先优化大文件上传体验，增加断点续传和进度预估。

#### 阶段 4：预览AI脚本（Preview Script）

| 维度 | 内容 |
|------|------|
| 情绪 | 😊 极佳 / Pain Level: 2 |
| 用户目标 | 查看AI生成的教学脚本，评估质量和可用性 |
| 触点 | 脚本生成等待页、脚本预览页面、原始材料 vs AI脚本对比视图 |
| 用户心声 | "哇，AI居然把我的录音拆成了5个知识点！""这段台词写得不错""但专业术语解释得不对" |
| 痛点 | 脚本生成需要等待1-3分钟；AI对专业术语理解偶有偏差；缺乏优秀脚本范例参考 |
| 机会点 | 脚本生成时展示实时进度；提供同课程优秀脚本范本；支持逐段对比原始材料和AI改写 |

**分析**：这是教师旅程中第一个"Aha Moment"——看到AI将自己的录音拆分为结构化的教学脚本时，教师会产生强烈的价值认同。

#### 阶段 5：审核修改（Review & Edit）🔑 Moment of Truth

| 维度 | 内容 |
|------|------|
| 情绪 | 😕 困惑 / Pain Level: 4 |
| 用户目标 | 精细编辑脚本内容，确保知识点准确无误 |
| 触点 | 脚本编辑器（类 Notion 富文本）、实时预览窗、修改标记/高亮系统 |
| 用户心声 | "这个公式描述需要更精确""修改完能实时看到变化吗？""改太多了，是不是AI质量不行？" |
| 痛点 | 编辑器功能不够强大（缺公式编辑器）；修改后无法直观看到动画效果变化；大量修改耗时 |
| 机会点 | 集成 LaTeX 公式编辑器；修改区域实时关联动画预览；AI 智能建议标记可能需修改的段落 |

**分析**：这是教师旅程的 Moment of Truth——脚本编辑体验直接决定教师是否继续使用平台。如果编辑体验流畅，教师会建立"AI生成+人工微调"的工作习惯；如果编辑痛苦，教师可能认为"还不如自己做PPT"。

#### 阶段 6：确认生成动画（Generate Animation）

| 维度 | 内容 |
|------|------|
| 情绪 | 😐 平淡 / Pain Level: 3 |
| 用户目标 | 确认脚本无误后启动动画渲染流程 |
| 触点 | 确认生成按钮、动画模板选择器、渲染进度条+预估时间 |
| 痛点 | 渲染耗时3-5分钟；模板选择有限（3-5套）；无法预览渲染中间结果 |
| 机会点 | 提供渲染时间预估和后台运行；渲染完成推送通知；支持草稿预览（低分辨率快速版） |

#### 阶段 7：预览动画课（Preview Animation）⚠️ Dropout Risk

| 维度 | 内容 |
|------|------|
| 情绪 | 😕 困惑 / Pain Level: 4 |
| 用户目标 | 观看完整动画，检查画面、配音、节奏是否满意 |
| 触点 | 动画预览播放器、时间轴标注系统、重新渲染触发按钮 |
| 用户心声 | "配音有点机械""这段动画节奏太快了""画面还行，但跟洋葱学院比差一些" |
| 痛点 | 动画质量低于洋葱学院精制水准；配音自然度不足；发现问题后需整体重新渲染 |
| 机会点 | 时间轴标注精确指出问题段落；支持单独重新渲染某一段；多种TTS音色可选 |

**分析**：这是教师旅程情绪最低的阶段，也是最大的 Dropout Risk。教师在经历了上传→编辑→等待后，如果动画质量不达预期，累积的挫败感会导致放弃。关键缓释措施：① 管理预期（宣传时强调"可用"而非"精美"）；② 支持分段重渲染降低修改成本。

#### 阶段 8：发布课程（Publish）

| 维度 | 内容 |
|------|------|
| 情绪 | 🙂 满意 / Pain Level: 2 |
| 用户目标 | 将满意的动画课程发布给学生 |
| 触点 | 发布设置页面、课程信息表单、发布确认弹窗、分享链接生成 |
| 痛点 | 发布表单字段较多；无法设置定时发布；缺少发布前最终检查清单 |
| 机会点 | 一键继承脚本中的标题/描述/标签；发布前 Checklist 自动检查；生成学科标签推荐 |

#### 阶段 9：查看学生数据（Analytics）★ Delight

| 维度 | 内容 |
|------|------|
| 情绪 | 😊 极佳 / Pain Level: 1 |
| 用户目标 | 了解学生的学习情况和答题表现 |
| 触点 | 数据仪表盘、课程级数据报告、学生答题热力图 |
| 用户心声 | "原来80%的学生在二叉树这里答错了""这个知识点是不是我讲得不够清楚？" |
| 痛点 | 数据维度有限（初期只有基础指标）；无法导出报告；缺少横向对比 |
| 机会点 | 数据飞轮：答题数据→优化出题引擎；生成教学改进建议报告；支持数据导出 |

**分析**：这是教师旅程的情绪峰值，也是数据飞轮的启动点。教师看到学生的学习数据后，会产生"优化课程"的动力，从而重新进入"审核修改→重新渲染→发布"的循环，形成教师侧的正反馈。

### 2.2 教师旅程关键洞察

1. **最大的 Dropout Risk 集中在"上传材料"和"预览动画课"两个阶段**，前者是技术体验问题（上传速度），后者是产品质量问题（动画质量）。
2. **Moment of Truth 在"审核修改"阶段**，脚本编辑器的体验质量直接决定教师是否建立长期使用习惯。
3. **情绪曲线呈"W形"**：满意→困惑→满意→困惑→平淡→困惑→满意→极佳，说明教师在"等待"和"质量评估"环节最容易产生负面情绪。
4. **数据飞轮是教师留存的关键**：当教师看到学生答题数据并据此优化课程时，平台从"工具"变成了"教学助手"。

## 三、学生旅程详细分析

**Persona**：王同学 / 大二计算机科学专业，20岁，习惯用手机碎片化学习  
**JTBD**：用最短的时间理解一个知识点，通过有趣的动画和即时练习加深记忆，考试前能高效复习

### 3.1 阶段详细数据

#### 阶段 1：发现课程（Discovery）

| 维度 | 内容 |
|------|------|
| 情绪 | 😐 平淡 / Pain Level: 3 |
| 用户目标 | 找到老师推荐的动画课程平台 |
| 触点 | 课程群分享链接、搜索引擎、同学/老师推荐、学校教务通知 |
| 痛点 | 不知道平台的存在；不清楚与传统MOOC的区别；需要额外注册新平台 |
| 机会点 | 与学校教务系统集成；微信小程序直接打开（免注册体验）；突出差异化 |

#### 阶段 2：浏览课程列表（Browse Courses）⚠️ Dropout Risk

| 维度 | 内容 |
|------|------|
| 情绪 | 😕 困惑 / Pain Level: 4 |
| 用户目标 | 找到自己需要的课程并判断是否值得学习 |
| 触点 | 课程列表页、搜索/筛选功能、课程卡片、试听预览 |
| 用户心声 | "哪门课是我的老师发布的？""课程太少了""这个难度适合我吗？" |
| 痛点 | 初期课程数量有限；搜索和筛选体验不够智能；无法快速判断课程质量 |
| 机会点 | 个性化推荐（基于学校/专业/年级）；30秒试听预览；难度标签+评分系统 |

**分析**：这是学生旅程的第一个关键风险点。初期课程数量必然有限，需要通过精准的推荐和快速试听来弥补内容不足的短板。建议优先实现"老师推荐"筛选器——学生最关心的是自己老师发布的课程。

#### 阶段 3：开始观看动画（Watch Animation）🔑 Moment of Truth

| 维度 | 内容 |
|------|------|
| 情绪 | 😊 极佳 / Pain Level: 2 |
| 用户目标 | 通过有趣的动画快速理解知识点 |
| 触点 | 动画播放器、字幕/笔记功能、倍速控制、书签功能 |
| 用户心声 | "哇，这个动画还挺有意思的！""节奏刚刚好""配音如果能更自然就完美了" |
| 痛点 | 配音机械感影响沉浸感；无法倍速播放；缺少书签功能 |
| 机会点 | 倍速播放+字幕同步；书签/笔记功能；弹幕式互动标记"没看懂" |

**分析**：这是学生旅程的 Moment of Truth——动画的第一印象决定学生是否继续使用平台。"5分钟搞懂一个知识点"的核心价值主张在此阶段验证。

#### 阶段 4：遇到弹出题目（Quiz Pop-up）

| 维度 | 内容 |
|------|------|
| 情绪 | 😐 平淡 / Pain Level: 3 |
| 用户目标 | 理解题目并检验自己对刚学内容的掌握程度 |
| 触点 | 弹出题目浮层、题目卡片、选项按钮、代码编辑器（编程题） |
| 痛点 | 题目难度可能不匹配；弹出时机可能打断观看节奏；编程题环境加载慢 |
| 机会点 | 自适应难度；允许跳过不打断心流；题目与知识点时间戳关联 |

#### 阶段 5：答题+看解析（Answer & Review）⚠️ Dropout Risk

| 维度 | 内容 |
|------|------|
| 情绪 | 😕 困惑 / Pain Level: 4 |
| 用户目标 | 了解答案是否正确，通过解析理解错误原因 |
| 触点 | 答题反馈动画、AI解析面板、关联视频片段、代码运行结果 |
| 用户心声 | "选错了，看看解析""解析写得还算清楚""答对了！解析可以跳过吗？" |
| 痛点 | 答错后缺乏针对性补救；解析质量不稳定（AI生成）；答对时强制看解析浪费时间 |
| 机会点 | 答错→自动推送相关视频片段；答对→跳过解析或显示进阶挑战题；可视化解析 |

**分析**：这是学生旅程情绪最低的阶段。答错题目本身就带来挫败感，如果解析不够清晰或缺乏补救措施，学生会产生"还不如直接看教材"的想法。关键改进：答错后自动推送相关视频片段，形成"看→练→补"的闭环。

#### 阶段 6：继续观看（Continue Watching）↗ Recovery

| 维度 | 内容 |
|------|------|
| 情绪 | 🙂 满意 / Pain Level: 2 |
| 用户目标 | 完成剩余动画内容，构建完整知识体系 |
| 触点 | 动画播放器（恢复）、进度条、段落小总结弹窗 |
| 痛点 | 注意力随时间递减；后半段内容难度不一致；缺少分段标记 |
| 机会点 | 分段标记+段落小总结；后半段适当加速；进度条成就系统 |

**分析**：这是 Recovery 阶段——学生从答题的挫败中恢复，继续观看动画。答题后继续看的设计是好的，但需要在后半段增加段落小总结来帮助学生回忆前面的知识点。

#### 阶段 7：完成课程（Complete Course）★ Delight

| 维度 | 内容 |
|------|------|
| 情绪 | 😊 极佳 / Pain Level: 1 |
| 用户目标 | 获得完课成就感，了解自己的学习成果 |
| 触点 | 完课庆祝动画、答题统计卡片、完课证书/徽章、社交分享按钮 |
| 用户心声 | "太棒了，5分钟就学完了一个知识点！""下一个知识点是什么？继续学！" |
| 痛点 | 缺少完课证书或徽章激励；不知道下一步应该学什么；完课后没有知识回顾 |
| 机会点 | 完课证书/徽章（可分享）；后续课程推荐+学习路径；个人学习报告（雷达图） |

**分析**：这是学生旅程的情绪峰值。完课时的成就感是驱动学生继续学习下一个知识点的核心动力。建议在此阶段重点投入激励设计（证书、徽章、社交分享）。

#### 阶段 8：获取复习指南（Study Guide）

| 维度 | 内容 |
|------|------|
| 情绪 | 🙂 满意 / Pain Level: 2 |
| 用户目标 | 获得系统化的复习资料，为考试做准备 |
| 触点 | 复习指南页面、考情情报表、知识点卡片（S/A/B级）、下载/打印功能 |
| 痛点 | 复习指南可能不够完整；无法下载为PDF打印版；知识点优先级标记不够直观 |
| 机会点 | 一键生成PDF/打印版；知识点按重要性分级+颜色编码；错题本汇总 |

#### 阶段 9：复习备考（Exam Prep）

| 维度 | 内容 |
|------|------|
| 情绪 | 😐 平淡 / Pain Level: 3 |
| 用户目标 | 使用复习指南高效备考，通过考试 |
| 触点 | 复习模式（知识点卡片轮播）、模拟题练习、错题回顾、倒计时日历 |
| 痛点 | 模拟题数量有限；知识点覆盖不够全面；缺少科学的复习时间规划 |
| 机会点 | 倒计时复习计划（基于考试日期自动排期）；弱项强化推送；AI预测考题 |

### 3.2 学生旅程关键洞察

1. **Moment of Truth 在"开始观看动画"阶段**，动画的第一印象（有趣、节奏好、配音自然）决定学生是否继续使用平台。
2. **最大的 Dropout Risk 在"浏览课程列表"和"答题+看解析"**：前者是内容供给问题（课程太少），后者是学习体验问题（答错的挫败感）。
3. **情绪曲线呈"V-W-V"形**：平淡→困惑→极佳→平淡→困惑→满意→极佳→满意→平淡，说明"观看"和"完成"是情绪高点，"寻找"和"答题"是情绪低点。
4. **复习指南是连接"学习"和"考试"的桥梁**：这是智课工坊区别于其他动画课平台的关键功能——不只是看动画，还帮学生备考。

### 3.3 学生 Onboarding 旅程：21天学习引导计划

> **设计灵感**：借鉴帧我 Alcheme 的 21 天习惯养成机制——通过渐进式里程碑和仪式感奖励，将"注册即流失"转化为"逐步建立学习习惯"。

学生注册后的前 21 天是留存黄金窗口。传统平台依赖用户自发探索，导致大量注册后沉默用户。智课工坊应设计一条**显性的引导路径**，让学生在关键时间节点获得明确任务和奖励，逐步从"被动注册"过渡到"主动学习"。

#### 里程碑设计

| 时间节点 | 里程碑名称 | 引导任务 | 奖励机制 | 情绪设计 |
|---------|-----------|---------|---------|---------|
| Day 0 | 启程 | 完成注册 + 选择学校/专业 + 加入老师班级 | 生成专属"学习名片"（可分享） | 归属感："我是XX大学CS专业的学习者" |
| Day 1 | 初体验 | 观看第一部动画课程（推荐老师发布的第一节课） | "破冰者"徽章 + 完课庆祝动画 | 成就感："5分钟就学完了一个知识点！" |
| Day 3 | 首次挑战 | 完成第一次答题互动（弹出题目） | "勤学"徽章 + 答题正确率展示 | 参与感："原来边看动画边做题是这样的体验" |
| Day 7 | 一周坚持 | 累计观看 3 节课 + 完成 5 道题 | "周冠军"徽章 + 学习周报（观看时长/答题统计） | 仪式感："我已经坚持一周了" |
| Day 14 | 知识收割 | 生成第一份复习指南（自动汇总已学内容） | "学霸"徽章 + 复习指南 PDF 下载 | 实用感："这东西考试真的用得上" |
| Day 21 | 习惯养成 | 累计学习 7 节课 + 正确率达标 + 生成 2 份复习指南 | "毕业生"称号 + 学习成就分享卡片 | 认同感："这个平台确实帮到我了" |

#### 引导触点与推送策略

| 阶段 | 推送渠道 | 推送时机 | 推送内容 |
|------|---------|---------|---------|
| Day 0-1 | 站内引导 + 微信小程序通知 | 注册后即时 | "你的老师李老师刚发布了《二叉树入门》，5分钟就能看完" |
| Day 2-3 | 微信服务号模板消息 | 每天 19:00（学习高峰期） | "你已经看了1节课，再答一道题就能解锁'勤学'徽章" |
| Day 4-7 | 站内通知 + 学习日历标记 | 每天 20:00 | "本周你还差1节课就能获得'周冠军'，点击继续学习" |
| Day 8-14 | 微信服务号 + 班级排行榜 | 隔天推送 | "你的复习指南已就绪，包含3个S级知识点，考前必看" |
| Day 15-21 | 成就系统 + 社交分享引导 | 里程碑达成时 | "恭喜获得'毕业生'称号！分享你的学习成就到朋友圈" |

#### Dropout 风险与对策

| 风险节点 | 流失原因 | 对策 |
|---------|---------|------|
| Day 1-2 | 注册后忘记平台 | 老师在课程群@全体提醒 + 首课推送精确到具体课程名 |
| Day 4-6 | 新鲜感消退 | 班级排行榜激发竞争心理 + "差一点就解锁"的损失厌恶话术 |
| Day 8-13 | 考试季时间冲突 | 主动推送"考前速成"复习指南 + 将学习行为与备考直接挂钩 |
| Day 15-20 | 课程供给不足 | 推荐同校其他老师的课程 + 开放"许愿"功能（学生投票想学的知识点） |

#### 与主旅程的关系

21 天 Onboarding 旅程并非替代主旅程（9 阶段），而是作为一条**覆盖层**运行在主旅程之上。它解决的是"学生注册后到形成使用习惯之间"的空白期——这段时间传统旅程图没有覆盖，但恰恰是用户流失最严重的阶段。

```
主旅程：  发现→浏览→观看→答题→完课→复习指南→备考
            ↑                              ↑
Onboarding：Day0启程 → Day1初体验 → Day3首挑战 → Day7周冠军 → Day14知识收割 → Day21习惯养成
```

Day 21 之后，学生已建立使用习惯，Onboarding 引导自动淡出，主旅程成为主导。

## 四、双旅程交叉分析

### 4.1 数据飞轮效应

```
教师上传更多课程 → 更多课程素材积累
        ↓
更多 few-shot 样本 → 脚本生成质量提升
        ↓
更好体验 → 更多学生使用 → 更多答题数据
        ↓
出题引擎学习优化 → 题目质量提升
        ↓
更高完成率 → 更多教师愿意使用（正循环）
```

### 4.2 关键交接点

| 交接点 | 教师侧 | 学生侧 | 设计机会 |
|--------|--------|--------|---------|
| 课程发布 | 教师点击"发布" | 学生在课程列表看到新课程 | 发布后自动推送通知给学生 |
| 答题数据 | 教师查看数据仪表盘 | 学生答题产生数据 | 实时数据同步 + 匿名聚合 |
| 课程优化 | 教师基于数据修改脚本 | 学生体验到更好的课程 | 标记"已优化"标签增强信任 |
| 复习指南 | 教师审核复习指南质量 | 学生使用指南备考 | 教师可查看指南使用率 |

### 4.3 共同的 Dropout Risk 模式

两条旅程的 Dropout Risk 都集中在**"等待"和"质量评估"**环节：
- 教师：上传材料（等待）、预览动画课（质量不达预期）
- 学生：浏览课程列表（找不到课程）、答题+看解析（解析不够清晰）

**统一设计策略**：在所有等待环节提供进度反馈和预估时间；在所有质量评估环节管理预期并提供快速修复路径。

## 五、优先级行动建议

### 5.1 P0 — 黑客松期间必须做

| 行动 | 影响的阶段 | 理由 |
|------|-----------|------|
| 上传进度条 + 预估时间 | 教师-上传材料 | 解决最大 Dropout Risk 的技术体验问题 |
| 脚本编辑器集成 LaTeX | 教师-审核修改 | Moment of Truth，编辑器体验决定去留 |
| 分段重渲染 | 教师-预览动画课 | 降低修改成本，缓解 Dropout Risk |
| 30秒试听预览 | 学生-浏览课程列表 | 弥补课程数量不足，降低选择困难 |
| 答错→推送相关视频片段 | 学生-答题+看解析 | 形成"看→练→补"闭环，缓解 Dropout Risk |
| 完课证书/徽章 | 学生-完成课程 | 强化 Delight 峰值，驱动持续学习 |

### 5.2 P1 — 孵化期优先做

| 行动 | 影响的阶段 | 理由 |
|------|-----------|------|
| 数据仪表盘 + 教学改进建议 | 教师-查看数据 | 启动数据飞轮，增强教师留存 |
| 个性化课程推荐 | 学生-浏览课程列表 | 解决初期课程数量不足的问题 |
| 复习指南 PDF 导出 | 学生-获取复习指南 | 连接学习与考试，差异化功能 |
| 倒计时复习计划 | 学生-复习备考 | 增加平台在考试季的使用频率 |
| 21天学习引导旅程 | 学生-全旅程 | 借鉴 Alcheme 里程碑机制，降低注册后沉默率，培养学习习惯 |

### 5.3 P2 — 产品化期规划

| 行动 | 影响的阶段 | 理由 |
|------|-----------|------|
| 微信/钉钉 SSO 登录 | 教师-注册、学生-发现课程 | 降低注册门槛 |
| 自适应出题难度 | 学生-遇到弹出题目 | 提升答题体验，减少挫败感 |
| 学习路径规划 | 学生-完成课程 | 驱动学生持续学习，提升 LTV |
| AI 预测考题 | 学生-复习备考 | 高价值差异化功能 |

## 六、度量建议

### 6.1 教师侧核心指标

| 指标 | 计算方式 | 目标值 |
|------|---------|--------|
| 课程完成率 | 发布课程数 / 开始上传课程数 | ≥ 60% |
| 脚本采纳率 | AI脚本无需大改的比例 | ≥ 70% |
| 平均制作时间 | 从上传到发布的平均耗时 | ≤ 30分钟 |
| 教师留存率 | 30天内再次创建课程的教师比例 | ≥ 40% |

### 6.2 学生侧核心指标

| 指标 | 计算方式 | 目标值 |
|------|---------|--------|
| 课程完成率 | 完整观看课程的学生比例 | ≥ 60%（vs MOOC 的 <10%） |
| 答题参与率 | 弹出题目时参与答题的比例 | ≥ 80% |
| 答题正确率 | 学生答题的平均正确率 | 50-70%（太高太低都不好） |
| 复习指南使用率 | 完课后下载复习指南的比例 | ≥ 30% |
| Day 1 回访率 | 注册次日再次登录的比例 | ≥ 50% |
| Day 7 留存率 | 注册 7 天后仍活跃的比例 | ≥ 35% |
| Day 21 转化率 | 完成 21 天 Onboarding 全部里程碑的比例 | ≥ 20% |
