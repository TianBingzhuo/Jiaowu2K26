# AdventureX 2026 终极指南核对摘要

> **用途：**赛事现场前的合规、提交与资源核对单，不是项目实现说明。
> **核对时间：**2026-07-21（Asia/Shanghai）。官方文档显示最新修改时间为 2026-07-20；规则仍可能继续更新。
> **主事实源：**[AdventureX 2026 终极指南（公开）](https://adventurex.feishu.cn/docx/FOhLdr0Y3okbATxWvBQcoFx0nEd)。如本页与后续官方通知或主办方解释冲突，以后者为准。

## 一页结论

- 活动日期为 **2026-07-22 至 07-26**；开幕式于 07-22 晚举行，开幕式结束后正式 Hacking。
- 主题和赛道在 **07-22 晚开幕式同时公布**，赛前不公布。
- 每队选择 **且只能选择 1 个主题**，并可选择 **1–6 个赛道**；旧材料中的“最多 8 个赛道”已经失效。
- 团队人数为 **2–4 人**，每人只能参加一个团队；没有完成组队会被视为没有完成项目。
- 允许赛前构思 Idea 或做有限的上手尝试；禁止提前完成大部分内容、复用旧项目、为旧项目增加功能，或直接拿公司 / Startup 产品参赛。
- 项目必须是可运行的技术产品；文章、视频、方案或 PPT 本身不能算完成。Expo 要展示产品，即使未全部完成也要展示实际构建结果。
- 项目提交通道于 **07-25 12:00** 开放，**07-26 01:00** 截止；截止后的内容和代码不进入评定。
- 评审看重 **创意、技术复杂性、社会影响力**；每位评委交流约 2–3 分钟。
- 可以使用 AI 辅助部分编码，但官方明确写明不能让全部代码均由 AI 生成；项目还须保持原创、合法合规。

## 赛前红线：本项目当前可以和不可以做什么

### 可以继续

- 整理公开规则、赞助权益、官方文档和来源链接；
- 定义问题、用户、范围、数据合同草案、决策闸门和现场任务卡；
- 构思 Idea，并将旧材料隔离为历史来源；
- 讨论技术候选、许可证、风险、回退和验证顺序；
- 招募队友、核对账号设备和演示职责。

### 现在不要做

- 创建本届功能仓库、功能代码、可运行原型、数据库或模型调用链；
- 在任何旧项目上提交 PR 或新增功能后拿来参赛；
- 将公司 / Startup 产品换名后参赛；
- 把归档旧页面、旧 PPT、旧 Demo 或供应商示例称为本届成果；
- 让外部非参赛者、指引者或 AI 代替团队完成全部项目代码。

### 开赛时的证据动作

1. 保存开幕式后的规则与主题 / 赛道快照；
2. 记录正式开赛时间；
3. 创建全新仓库并保留首个空白提交时间；
4. 记录赛前资料与现场代码的边界；
5. 为每项功能保留任务卡、提交、测试与失败记录。

## 提交字段清单

United Portal 的提交至少要准备：

1. 作品名称；
2. 一句话简介；
3. 支持 Markdown 的详细描述；
4. 使用的技术；
5. 至少一张图片或视频轮播素材，第一张为 16:9 封面；
6. 且只能选择 1 个主题；
7. 1–6 个赛道；
8. 完整队友信息（本人之外最多 3 人）；
9. GitHub 仓库链接；
10. 带官方要求标签的小红书图文或视频链接；
11. 可选的项目体验链接；
12. 部分赛道要求的文书回答。

代码需上传 GitHub，并按指南设置 `#adventurex2026` Tag。指南还要求准备 Expo Slide Show；但评审希望看到可操作产品，幻灯片不能替代产品演示。

## 展示与评审注意

- 至少一名队员必须在 Expo 现场演示；要获得奖项，指南要求全组成员在评判期间亲自出席。
- 每位评委交流时间约 2–3 分钟，演示必须先出现问题、实际操作和结果，再补充架构与愿景。
- 三项主题评判标准为：创意、技术复杂性、社会影响力。
- 赛道要求必须逐条核对。若项目偏离超过 2 个赛道要求；不足 2 个赛道时按 1 个计算，指南写明可能影响次年参赛资格。
- 部分赛道有额外文书题，不能等到截止前才阅读。

## 对 jiaowu2K26 的直接影响

1. **维持赛前纯文档状态。** 当前整理没有越过官方边界。
2. **开幕式后才锁技术栈。** 主题、赛道和精确赛道要求仍未知，不能现在把赞助资源写成最终方案。
3. **P0 更应收紧。** 官方评审时间短，最强演示仍是“来源 → 草稿 → 教师审核 → 发布 → 学生互动”的一条可操作闭环。
4. **AI 代码要有人类所有权。** 团队必须能解释、修改和演示现场代码，不把全部实现交给生成式工具。
5. **提交物从第一天维护。** GitHub、16:9 封面、小红书内容、技术说明、主题 / 赛道选择和额外文书都要进入现场任务板。

## 仍需开幕式后确认

- 五个主题的精确定义；
- 各赛道的逐条要求、文书题、奖项与兼容关系；
- 硬件的精确 SKU、数量、领用 / 归还、配件和技术支持时段；
- 软件权益的领取入口、账号、限流、数据保留、地区与有效期；
- United Portal 当天实际字段、上传大小和故障回退；
- GitHub Tag 的具体形式及主办方是否另有仓库可见性要求。
