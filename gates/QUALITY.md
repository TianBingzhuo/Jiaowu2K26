# 通用质检标准

> **用途**：贯穿 GATE-0 → GATE-3 所有阶段的质量检查基准
> **引用**：各 Gate 文件引用本文件作为通用质检依据
> **来源**：[PLAYBOOK.md](../archive/superseded-8entries-20260721/PLAYBOOK.md) Claim Ledger、[Demo数据包说明](../archive/original-materials/智课工坊_Demo数据包说明.md) 质量评审表

---

## 代码质检

- [ ] 无硬编码密钥 / 令牌 / 密码
- [ ] 所有外部依赖有版本锁定（package.json / Cargo.lock / requirements.txt）
- [ ] 错误处理覆盖主路径（try-catch / Result / 错误码）
- [ ] 代码可被任何队友理解和修改（有注释、有 README）
- [ ] 密钥只放受控环境变量 / 秘密管理，不回显、不提交
- [ ] 学生/课程数据最小化；演示优先虚构/授权样例
- [ ] 日志中删除不必要内容；对外分享前脱敏

---

## UX 质检

- [ ] 核心流程可在 2 分钟内走通
- [ ] 所有页面使用同一全局 Shell、Design Tokens、组件、图标、动效和任务循环；没有模块私有换肤
- [ ] 学生 MyCareer、教师 Coach Studio、学校 Front Office 只改变权限与密度，并排截图仍像同一款游戏
- [ ] 页面遵循 `Briefing → Choose → Execute → Replay → Next Move`，正式状态、来源与下一步高于装饰
- [ ] 错误状态有友好提示（网络错误 / 服务不可用 / 数据异常）
- [ ] 加载状态有进度指示（骨架屏 / spinner / 进度条）
- [ ] 空状态有引导提示（"暂无数据" / "开始创建"）
- [ ] 两种屏幕尺寸（笔记本 1440x900 / 手机预览）可用
- [ ] 键盘路径可走通核心流程
- [ ] 支持"减少动效"偏好（prefers-reduced-motion）
- [ ] 对比度满足 WCAG AA 标准
- [ ] 沉浸 / 轻量 / 传统 / 减少动效模式的信息完整度一致，传统模式不是粗糙后台
- [ ] 无未经登记的 raw hex、字体、emoji 图标、临时插画或不同画风素材
- [ ] AI/规则建议同屏显示来源、证据状态、未知、替代项和人工纠正动作，不只显示孤立置信百分比
- [ ] 每个失败状态提供重试、人工接管或正式申诉路径；没有“只能关掉弹窗”的死路
- [ ] 高风险页面显示正式名称、责任方、当前状态、最后更新时间和下一步，游戏叙事不压过紧急动作
- [ ] 主视觉具备学生英雄位、赛季上下文、一个主目标和可操作 HUD；不退化成赛博概念海报或通用 SaaS Dashboard
- [ ] 对应的人因假设已经记录；首读理解、压力、公平、隐私、退出/申诉和可访问路径至少经过走查，真实参与者证据与样本局限按 [HUMAN-FACTORS](../product/HUMAN-FACTORS.md) 留档

---

## 数据质检

- [ ] AI 生成内容有至少 1 个可定位来源（source_ids 非空）
- [ ] 审核操作有追加式审计日志（append-only review_event）
- [ ] 模拟数据与真实数据使用不同标签（fixture / cache / live 状态可区分）
- [ ] Fixture / 缓存 / Live 状态不在同一界面混用相同状态标签
- [ ] 外部记录始终带来源、版本、获取时间和权威等级
- [ ] What-if 与正式结果在数据类型和界面文案上同时区分
- [ ] 模型/数据库/供应商 ID 不进入核心领域枚举，保持可替换
- [ ] 关键结果可展开稳定 Evidence Pack：事件 ID、操作者、前后状态、理由、来源、版本、时间、纠错/申诉
- [ ] 可重试外部动作有幂等键；失败、取消、回退和人工处理均可观察，不重复执行
- [ ] Intent Profile 与权威事实分离，目标/偏好可纠正、导出、删除和设置到期

## 合规质检

- [ ] 无 NBA / 2K 商标或受保护资产（借机制不借品牌）
- [ ] 无付费资格 / 排名 / 人员拍卖机制
- [ ] 无公开排行 / 羞辱标签 / 伪医学判断
- [ ] 学生控制非必需分享 / 匹配 / 导出（需明确同意）
- [ ] 课程材料、个人信息、密钥、第三方代码和媒体必须有权使用
- [ ] BGM 必须免版税，并记录来源
- [ ] 不使用真实学生姓名、学号、邮箱
- [ ] 不使用真实考试原题
- [ ] 开源 Lottie / 图片 / 字体素材记录 URL 和 license
- [ ] 支付、门禁、健康、安全、录取、资助、人事与晋升均保留正式名称、责任方、申诉和人工回退
- [ ] General Cash、Policy Balance、External Rails、Module Cap 与 Entitlement 没有混成单一可互换货币

## 故障回退质检

参考 [GATE-1-技术验证-6h.md](GATE-1-技术验证-6h.md) 技术回退表。

| 故障 | 现场行为 | 对评委的说法 |
|------|---------|-------------|
| 模型超时/额度 | 加载明确标注的规则/fixture 草稿，继续真实审核状态机 | "模型不可用，当前是回退输入；审核和发布仍实时" |
| OceanBase 不可用 | 切同 repository 合同的 SQLite | "主库连接失败，使用本地事务回退" |
| 无网络 | PWA/本地服务 + 已授权缓存；禁用正式外链动作 | "当前离线，来源快照时间为……" |
| 硬件断联 | 使用真实采集过的事件回放并标注 | "硬件不在线，播放的是已记录事件" |
| WinUI/3D 壳失败 | 直接打开 Web 主路径 | 不把壳当核心价值 |
| 新材料解析失败 | 展示部分成功、错误定位和手工来源片段 | 不伪装为通用一键解析 |

## 内部 Hackathon Readiness Rubric（非 AdventureX 官方评分）

本表用于团队自检，综合了本地黑客松评分表、成品复盘、ProductMap 和挑战杯证据链方法。原始本地评分表五项合计为 85 分，不能被描述成 AdventureX 2026 官方百分制；这里额外加入证据治理形成团队内部 100 分制。

| 维度 | 分值 | 高分口径 |
|---|---:|---|
| 场景价值 | 20 | 用户、痛点、频率、现有替代和任务闭环清楚；不是想象出来的“大市场” |
| 核心闭环 | 20 | 一条 Magic Moment 可真实操作，输入、状态变化、输出和下一步完整 |
| 技术推理与鲁棒性 | 20 | 架构服务于不变量；正常、失败、回退、离线和人工接管都能解释/验证 |
| 工具与资源整合 | 10 | 赞助模型、数据库、开源或硬件按真实价值采用，有版本、许可证和替代方案 |
| UX、游戏感与可访问性 | 15 | 三秒看懂当前目标；像同一款游戏；键盘、对比度、减少动效、降噪模式完整 |
| 证据、治理与路演 | 15 | 声称有来源/分母/版本/限制；权限与申诉清楚；90 秒演示及完整备份可用 |
| **总计** | **100** | 低于 70 不扩支线；任何合规、安全或 P0 闭环 Blocker 均不得以总分抵消 |

## Claim Ledger（路演表述核查）

**原则**：没有现场实现与证据的能力只能写"计划/愿景/候选"。

| 说法 | 证据状态 | 可以说？ | 实现后要求 |
|------|---------|---------|-----------|
| "AI 必须亮出来源" | [赛后实现状态] | 实现了才能说 | 至少一个真实来源闭环 |
| "教师审核后才能发布" | [赛后实现状态] | 实现了才能说 | 操作、提交、测试记录 |
| "可追溯的证据链" | [赛后实现状态] | 实现了才能说 | 至少一个真实来源闭环 |
| "能降低审核时间" | [赛后实现状态] | "希望验证是否降低" | 样本、分母、中位数、限制 |
| "能提升学习效果" | 未验证 | 不作结果性声明 | 需要独立研究设计，不由黑客松小样本证明 |
| "Rust/OceanBase 已采用" | [赛后实现状态] | "前6h验证后决定" | 版本、测试、回退证据 |
| 任何"已完成"/"已达到"的表述 | 必须有代码/数据证据 | 无证据不可说 | — |
| "2K 官方合作/授权" | 不成立 | 不说 | 除非未来获得书面授权 |
| "NBA 2K 截图可作产品资产" | 不成立 | 只说内部研究 | 不进入提交产品 |

### Claim Ledger 使用规则

1. 路演前逐条过 Claim Ledger，每条说法有对应证据
2. 未实现的功能用"我们准备验证……""P0 目标是……"表达
3. 数字有来源、分母、样本量和方法说明
4. 总项目愿景、P0、现场实现和路线图明确区分

## 开源采用模板

每个外部依赖必须登记以下信息：

```yaml
component:              # 组件名称
upstream_repository:    # 上游仓库
selected_version_or_commit:  # 版本或 commit
registry_or_download_url:    # 下载地址
sha256:                 # SHA-256
license_spdx:           # SPDX 许可证标识
license_and_notice_preserved: []  # 保留的许可证和通知
transitive_license_check: pending # 传递依赖许可证检查
reuse_mode:             # direct_dependency | adapted_snippet | reference_only
project_role:           # 在项目中的角色
local_modifications: [] # 本地修改
security_check: pending # 漏洞/恶意代码/维护状态检查
event_rule_check: pending # 赛前资产与本届规则检查
fallback:               # 回退方案
```

## 数据目录质检

├── source/        # 授权输入与版本
├── generated/     # 现场输出与 source IDs
├── reviews/       # 审核事件与人工核对
├── metrics/       # 运行、成本、失败和测试
└── provenance/    # 依赖、模型、资产、规则、版本、许可、哈希
