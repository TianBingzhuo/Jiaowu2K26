# 智课工坊（SmartCourse Studio）路演框架

**路演场景**：黑客松，5分钟路演 + 3分钟Q&A
**受众**：评委（技术 + 商业背景混合）
**核心目标**：让评委在5分钟内理解"这是什么、为什么牛、为什么现在"，并在Q&A中展现深度思考
**文档版本**：v1.0
**日期**：2026-06-23

---

## 〇、路演口径更新

为适配 AdventureX 2026 的黑客松场景，路演表达优先证明“可运行闭环”，避免把原型讲成已经商业验证的成熟平台。

| 原说法 | 建议说法 | 原因 |
|--------|----------|------|
| 洋葱学院级动画课 | 洋葱式短动画互动课 | 避免承诺达到头部人工精制质量 |
| AI实时出题每个学生都不同 | AI基于当前脚本生成题目，后续可个性化 | 黑客松阶段先证明生成能力 |
| 6个月20所签约大学 | 6个月验证20门试点课程/合作线索 | 更符合早期项目现实 |
| 99元/门课起步 | 课程试点包 + 院系订阅 | 避免被锁死在过低定价 |
| 数据飞轮已是壁垒 | 数据飞轮是可形成的长期壁垒 | 早期数据量不足，先讲机制 |

现场主线：P0为“教师材料 → AI脚本 → 教师审核 → 动画/图文播放 → AI出题”；P1为复习指南、代码练习、TTS配音；P2为Computer Use、大学配置、BGM概念展示。

## 一、路演结构设计（10页PPT，5分钟）

### 设计原则

- 标准投资人Deck为12页，黑客松场景压缩至10页
- 每页一个Key Message，不超过6个bullet point
- 字号不小于24pt，数据可视化优先于文字
- Storytelling Arc：**Hook（1-2页）→ Build（3-5页）→ Prove（6-7页）→ Close（8-10页）**
- Demo是黑客松路演的灵魂，分配最多时间

### 逐页设计

| 页码 | 标题 | 时间 | 核心信息（Key Message） | 视觉元素 | 备注 |
|------|------|------|------------------------|---------|------|
| P1 | 封面 | 15s | "智课工坊——让大学教师快速生成短动画互动课" | 产品名称 + 一句话定位 + 团队Logo | 开场即传递愿景，不要念标题 |
| P2 | 问题 | 30s | "大学网课完成率全球低于10%，因为60分钟的录播课没人看得下去" | 数据大字 + 对比图（洋葱5min vs MOOC 60min） | 用具体场景共鸣，不用抽象描述 |
| P3 | 解决方案 | 30s | "教师上传录音 → AI生成动画课 → 学生边看边答题，全程不超过10分钟操作" | 三步流程图（极简icon风） | 强调"教师零门槛"和"5-8分钟节奏" |
| P4 | **Demo: 教师端** | 60s | "看，我只上传了一段录音，3分钟后就拿到了一个动画课程脚本" | **现场操作 / 录屏** | 这是全场的焦点，必须流畅 |
| P5 | **Demo: 学生端** | 45s | "学生看到的是一个5分钟动画，每2分钟弹出一道AI实时生成的题" | **现场操作 / 录屏** | 展示出题的"实时性"和"个性化" |
| P6 | 技术壁垒 | 30s | "我们不是一个工具，是一个数据飞轮" | 飞轮循环图（4个环节闭环） | 这是评委最关心的"为什么别人追不上" |
| P7 | 差异化竞争 | 20s | "洋葱学院不做大学，MOOC不做动画，我们占据交叉空白" | 2x2定位矩阵图 | 快速过，不要展开讲每个竞品 |
| P8 | 商业模式 | 20s | "B2B按校/院系订阅，客单价高、粘性强" | 三级定价简图 + 单位经济模型关键数字 | 黑客松不深究财务，但要展示商业sense |
| P9 | 路线图 & 验证 | 20s | "5天跑通闭环 → 2个月种子教师试点 → 6个月验证20门课程" | 时间轴（4个里程碑） | 展示执行力和节奏感 |
| P10 | CTA & 团队 | 10s | "我们正在寻找种子大学合作伙伴和天使投资人" | 团队照片 + 联系方式 + 二维码 | 最后一句话要有力，留下actionable的CTA |

**时间分配总计**：15+30+30+60+45+30+20+20+20+10 = **280秒 ≈ 4分40秒**，留20秒buffer。

### 叙事弧线映射

```
Hook (P1-P2):  用数据制造紧迫感——"10%完成率"这个数字要让评委皱眉
Build (P3-P5): 展示解决方案+Live Demo——让评委"哇"出来
Prove (P6-P7): 用数据飞轮+竞争定位证明壁垒——让评委点头
Close (P8-P10): 商业模式+路线图+CTA——让评委想参与
```

## 二、5分钟叙事脚本

> 以下为完整逐字稿参考，实际演讲时应自然表达，不要背诵。括号内为舞台指示。

### P1 封面（15秒）

> "各位评委好，我们是智课工坊。我们的愿景是——让每一位大学教师，都能快速生成一节短动画互动课。"
>
> （停顿，环视全场，开始翻页）

### P2 问题（30秒）

> "先看一组数据。全球大学在线课程的完成率，低于10%。也就是说，100个选课的学生里，只有不到10个人能看完。
>
> 为什么？因为现在的大学网课是这样的——（指向屏幕）一段60分钟的录播视频，教授对着PPT念，没有互动，没有反馈。
>
> K12里已经有人证明，短动画加练习比长录播更容易让学生坚持学下去。但问题是——大学课程的专业深度、公式、代码和软件操作，现有动画课产品很少覆盖；而大学教师自己，也没有时间去学动画制作。"

### P3 解决方案（30秒）

> "智课工坊解决的，就是这个断层。
>
> 教师只需要做一件事：上传一段课程录音或者课件PPT。剩下的全部由AI完成——转写、生成教学脚本、渲染动画、配音、出题。教师在中间有一个审核确认环节，可以微调脚本后再进入渲染。
>
> 学生拿到的，是一个5到8分钟的动画讲解，每2到3分钟弹出一道基于当前脚本生成的题目。答错了，系统可以推送对应的讲解片段。
>
> 整个过程，教师的操作时间不超过10分钟。"

### P4 Demo - 教师端（60秒）

> "接下来我给大家看一个真实的Demo。"
>
> （切换到Demo界面 / 播放录屏）
>
> "这是一段5分钟的《数据结构》课程录音，讲的是二叉搜索树。我现在上传到平台——
>
> 系统先用Whisper做语音转文字，然后LLM自动生成教学脚本。大家看这个脚本——它自动把知识点拆成了三个部分，每部分有讲解台词和动画指示。
>
> 教师可以在这里预览和修改脚本——比如我把这个例子换一下——确认后点击'生成动画'。
>
> （展示生成的动画片段）
>
> 这就是AI生成的动画课程。预制角色、自动配音、知识点可视化。从上传到成品，全程不到5分钟。"

### P5 Demo - 学生端（45秒）

> "现在切换到学生视角。"
>
> "学生打开这节课，看到的是一个5分钟的动画。播放到1分40秒——"
>
> （播放动画，题目弹出）
>
> "弹出了一道题。注意，这道题不是预制题库里的，而是AI根据刚才讲的脚本内容生成的。后续接入学习数据后，题目难度可以继续个性化。
>
> 我选一个答案——答错了。系统立刻推送了一段30秒的补充讲解，针对我理解错的那个知识点。
>
> 再看编程课的场景——（切换到代码编辑器）这里内嵌了Monaco Editor，学生可以直接在页面里写代码、运行、看到结果。这对于计算机课程来说是刚需。"

### P6 技术壁垒 - 数据飞轮（30秒）

> "可能有评委会问：这个事情的技术门槛不高，别人也能做。我们的回答是——我们不是一个工具，是一个数据飞轮。
>
> （指向飞轮图）
>
> 更多教师使用，意味着更多高质量教学脚本样本积累，脚本生成质量就更高。更多学生使用，意味着更多答题数据，出题引擎就能持续校准难度。更好的体验，又吸引更多教师和学生。
>
> 这个正反馈循环一旦转起来，后来者需要追赶的就不只是技术，而是数据、模板和教师工作流。这是我们长期要建立的壁垒。"

### P7 差异化竞争（20秒）

> "快速看一下我们的竞争定位。
>
> （指向2x2矩阵）
>
> 横轴是课程形式——传统录播 vs 动画互动。纵轴是受众——K12 vs 大学及以上。
>
> 洋葱学院在左上角，K12动画课，但不做大学。中国大学MOOC在右下角，大学课程，但全是60分钟录播。B站知识区是散乱的UGC。
>
> 右上角——大学动画互动课——这个象限目前是空白的。我们就是来占这个位置的。
>
> 另外，AI出题是我们的核心差异化；Computer Use软件教学是后续概念展示，尤其适合大学计算机课程。"

### P8 商业模式（20秒）

> "商业模式上，我们走B2B路线，面向大学和院系做SaaS订阅。
>
> 定价上先从课程试点包切入，再升级到院系订阅和学校定制。早期重点不是马上卖大单，而是拿到真实教师、真实课程和真实学生反馈。
>
> 为什么先做B2B？因为课程生产者是教师，学校和院系能提供课程、学生和教学场景。等试点数据成立后，再讨论校级采购会更自然。
>
> 长期来看，我们还会探索B2C（学生个人订阅考研/考证内容）和企业培训市场。"

### P9 路线图（20秒）

> "我们的执行节奏是这样的——
>
> 这个黑客松是第0阶段：跑通核心闭环，拿到评委和用户的初步反馈。

## 三、评委Q&A预案（18个高频问题 + 回答要点）

### 分类说明

| 类别 | 问题编号 | 评委关注点 |

| 技术深度 | Q1-Q5 | 技术方案可行性、壁垒真实性 |

| 商业模式 | Q10-Q12 | 定价、获客、单位经济 |
| 产品与体验 | Q13-Q15 | 内容质量、用户体验、教师采纳 |

### Q1: 动画质量能达到洋葱学院那种水平吗？

**回答要点**：
- 坦诚承认：短期内AI生成质量约为洋葱学院人工精制的70-80%
- 但关键洞察：洋葱学院一个5分钟视频的制作成本约5000-10000元，耗时1-2周；我们5分钟生成，边际成本趋近于零
- 我们的策略不是"追平洋葱"，而是"够用即可"——大学教师对动画质量的要求远低于K12学生，他们要的是"知识讲清楚了"
- 随着模板积累和用户反馈迭代，质量会持续提升

### Q2: AI生成的教学脚本质量不稳定怎么办？

**回答要点**：
- 这是我们识别的关键风险（R1），已有三层缓释机制：
  1. **多轮Prompt迭代**：针对每个学科建立专门的few-shot样本库
  2. **教师审核环节**：脚本生成后教师可预览修改，确认后才进入渲染——这是影响教师采纳意愿的核心设计
  3. **质量评分机制**：系统自动对脚本打分（知识点覆盖度、逻辑连贯性、时长合理性），低于阈值的自动提示教师修改
- 黑客松实测：计算机科学课程的脚本可用率（无需大改）约为70%，符合我们的预期

### Q3: "数据飞轮"听起来很好，但冷启动阶段怎么办？

**回答要点**：
- 冷启动的核心不是数据量，而是数据质量
- 第一步：团队自己制作10-20个高质量"黄金样本"作为few-shot种子
- 第二步：找1-2个种子大学的教师合作，他们的脚本和反馈就是第一批真实数据
- 第三步：学生的答题数据从第一天就开始积累，哪怕只有100个学生，也足够校准出题引擎的难度分布
- 飞轮不需要"大"才能转——小飞轮先转起来，验证闭环后再加速

### Q4: Computer Use教学具体怎么实现？技术可行性如何？

**回答要点**：
- 概念：用AI（如Anthropic Claude的Computer Use / PyAutoGUI）自动执行软件操作并录屏，生成"AI手把手教你用Git/VS Code/Photoshop"的动画教程
- 黑客松阶段：只做1个场景的概念验证（如"用Git提交代码"），用PyAutoGUI + 录屏实现
- 长期方案：结合大模型的Agent能力，让AI理解"教学意图"而非单纯执行命令——比如"教学生用git merge"时，AI会故意制造冲突然后演示如何解决
- 为什么这是壁垒：目前没有教育平台在做这件事，而且每个软件操作场景的自动化脚本都需要深度定制，先发者有场景积累优势

### Q5: 你们的技术栈选型理由是什么？为什么不自己开发动画引擎？

**回答要点**：
- 黑客松阶段：Lottie（预制角色）+ Framer Motion（微交互）+ HTML/CSS（场景布局），理由是最快出效果且充分利用预制素材
- 孵化期计划升级到Remotion（React视频框架），代码可控且可模板化
- **永远不自研动画引擎**——这是经过Impact/Effort评估后的明确决策。自研引擎是典型的Money Pit，ROI极低。我们的核心壁垒不在渲染技术，在数据飞轮和教师生态
- LLM选型：GPT-4/Claude用于脚本生成和出题（长文本理解+结构化输出），Whisper用于ASR，Edge-TTS用于配音（零成本）

### Q6: 大学网课完成率低于10%这个数据来源是什么？

**回答要点**：
- 来源：多项学术研究一致佐证。MIT与Harvard联合研究（2014-2018）显示MOOC课程完成率中位数约5-15%；Coursera官方数据曾披露整体完成率约15-20%（活跃学习者口径）；国内学堂在线等平台的公开数据也指向类似量级
- 关键区分："选课完成率"和"活跃完成率"差异很大，我们引用的是"选课到完课"的宽口径数据
- 如果评委追问具体论文：Christensen et al. (2013) "The MOOC Phenomenon" 和 MIT/Harvard 2019年发布的"Course Certificates" 系列报告

### Q7: 洋葱学院如果向上延伸到大学市场怎么办？

**回答要点**：
- 可能性存在，但概率不高，原因有三：
  1. **基因不同**：洋葱学院的核心能力是K12内容团队（编剧+动画师），大学课程需要的是学科专业知识，两种人才完全不同
  2. **商业模式差异**：洋葱是B2C（面向家长收费），大学市场是B2B（面向学校采购），销售体系和决策链完全不同
  3. **我们的时间窗口**：即使洋葱要延伸，至少需要12-18个月组建大学内容团队和B2B销售团队，这给了我们足够的先发时间
- 最坏情况：如果洋葱真的进场，我们已经有数据飞轮和大学渠道壁垒，被收购也是一种退出路径

### Q8: MOOC平台（中国大学MOOC/学堂在线/Coursera）如果加动画功能呢？

**回答要点**：
- MOOC平台加动画功能在技术上可行，但在组织上很难：
  1. 平台的核心能力是"连接"（连接教师和学生），不是"内容生产工具"
  2. 他们已有的海量录播内容是沉没成本，转向动画意味着否定过去的投入
  3. 即使做，大概率是"增加一个动画模板功能"，而非围绕"AI生成+实时出题"重新设计产品
- 我们的差异化不只是"有动画"，而是"教师零门槛自助生成"+"AI实时出题"+"数据飞轮"三者的结合
- 潜在合作机会：我们也可以作为MOOC平台的插件/供应商，而非直接竞争

### Q9: 你们说赛道"空白"，但B站知识区有很多好的教学UP主，这不就是UGC竞品吗？

**回答要点**：
- B站知识区是"注意力竞争者"而非"直接竞品"——它不是系统化的课程体系，而是碎片化的知识点
- 关键区别：
  1. B站UP主是手工制作（高门槛），我们是AI自动生成（零门槛）
  2. B站没有AI实时出题，没有学习反馈闭环
  3. 大学教师不会去B站发课程（品牌不符、版权顾虑），但愿意在学校官方平台使用我们的工具
- 但B站验证了一件事：年轻用户确实更喜欢"短小精悍+视觉化"的知识获取方式，这对我们是利好

### Q10: 早期定价怎么定？怎么支撑商业模式？

**回答要点**：
- 黑客松后不急着锁死单课价格，先做课程试点包，验证教师是否愿意持续使用
- 真正的商业化方向是院系级订阅和学校定制，按课程量、服务深度、数据分析能力定价
- 对标参考：一个院系一学期可能有30-50门课，适合按课程包或教学改革项目打包试点
- 单位经济模型：主要成本来自ASR、LLM和TTS调用，Day4会用真实token和耗时做保守核算
- 早期最重要的不是毛利率数字，而是证明三件事：教师省时间、学生愿意看、学校愿意继续试点

### Q11: B2B面向大学销售，决策链那么长，怎么获客？

**回答要点**：
- 短期策略（黑客松后6个月）：不走校级采购，而是找"创新型教师"个人合作
  - 很多大学教师有教学改革课题经费（几千到几万元），可以自主决策
  - 先用免费/低价让1-2个教师用起来，产生效果数据（完课率提升、学生满意度）
- 中期策略：有了效果数据后，通过"院系推荐→教务审批"的自下而上路径渗透
- 渠道合作：与高校教育技术中心、教师发展中心合作，他们有KPI推动教学创新
- 长期策略：积累到一定品牌后，参加教育展会、进入政府采购目录

### Q12: 如果大模型API成本上涨或者供应商涨价怎么办？

**回答要点**：
- 当前LLM API市场是"买方市场"——GPT-4、Claude、DeepSeek、通义千问等多家竞争激烈，价格趋势是持续下降
- 技术层面的应对：
  1. Prompt缓存——相似知识点的脚本可以复用部分prompt，减少token消耗
  2. 模型分层——简单任务（如ASR后处理）用小模型，复杂任务（如脚本生成）用大模型
  3. 抽象LLM接口层——后端已经设计为可切换模型供应商，不被单一API绑定
- 成本估算：按当前价格，生成一门5分钟动画课的API成本约5-10元，即使翻倍也在可接受范围

### Q13: 教师会不会觉得AI生成的脚本"不够专业"而不愿意用？

**回答要点**：
- 这正是我们在MVP中加入"教师审核编辑环节"（F14）的原因——教师不是被动接受AI产出，而是"AI起草 + 教师把关"
- 调研显示：教师最大的痛点不是"AI写得不好"，而是"我没有时间从零做动画"。只要AI能帮他们省80%的时间，他们愿意花20%时间做微调
- 产品设计上：
  1. 教师审核界面设计得足够简单——标注修改、一键确认
  2. 初期提供"学科模板"（如计算机科学专用模板、经济学专用模板），提升初始脚本质量
  3. 收集教师修改数据作为反馈信号，持续优化脚本生成模型

### Q14: AI实时出题的质量能保证吗？会不会出错题？

**回答要点**：
- 出题质量取决于脚本质量和prompt设计，当前准确率约80-85%（即80-85%的题目可以直接使用）
- 三层质量保障：
  1. **生成时**：题目必须包含答案解析，AI自检"题目-答案-解析"三者一致性
  2. **发布时**：教师审核环节也可以审核题目（可选）
  3. **使用后**：根据学生答题数据（正确率、区分度）自动校准题目难度——如果一道题90%的人都答对或都答错，系统自动标记为"需优化"
- 与预制题库相比：AI出题的优势是"个性化"和"无限题库"，但质量稳定性确实是需要持续迭代的方向

### Q15: 学生端的体验会不会变成"又一个被迫使用的学习平台"？

**回答要点**：
- 核心设计理念是"降低学习痛苦"而非"增加学习任务"：
  1. 5-8分钟的短视频节奏，符合注意力曲线
  2. 每2-3分钟的互动出题打破被动观看的枯燥感
  3. 答错后的针对性讲解（而非惩罚），让学习有"被辅导"的感觉
- 参考数据：洋葱学院在K12的实践中，动画+练习模式的学生满意度比纯视频课高出30-40个百分点
- 长期会引入游戏化元素（排行榜、成就系统、先测后学模式），但MVP阶段先验证核心体验

### Q16: 你们团队4个人，5天能做完这些东西吗？

**回答要点**：
- 我们有严格的优先级管理：按Impact/Effort矩阵筛选了14个创意，只做Quick Win象限（高Impact低Effort）的9个功能
- 5天排期已经精确到半天粒度，每天晚间有集成检查点
- 关键原则：Day2末必须跑通核心闭环（转写→脚本→动画→出题），后续时间用于打磨和扩展
- 如果时间不够，我们优先保Demo质量而非功能数量——一个完美的3分钟Demo比十个半成品更有说服力
- 已做减法：砍掉了学习社交（C7）、先测后学（C8）、考研扩展（C10）、自研动画引擎（C11）

### Q17: 如果这个方向验证失败，你们有Pivot计划吗？

**回答要点**：
- 核心假设的风险排序：脚本质量（子假设2）> 动画质量（子假设3）> 市场需求（子假设6）
- 如果"大学"方向验证失败，技术栈可以低成本Pivot到：
  1. **企业培训**：新员工入职培训、产品知识培训——企业付费意愿更强、决策更快
  2. **考研/考证培训**：用户付费意愿强、内容标准化程度高
  3. **K12延伸**：与现有K12教育公司合作，提供"教师自助生成"工具
- 底层能力（ASR→脚本→动画→出题pipeline）是通用的，换个场景只需要调整Prompt和模板

### Q18: 版权和知识产权怎么处理？

**回答要点**：
- 我们已设计清晰的版权框架：
  1. **教师原始材料**：版权归教师所有，上传即授权平台再分发权
  2. **AI生成的动画课程**：衍生权归平台，教师享有署名权和原样分发权
  3. **学生使用**：仅限个人学习，禁止商业化再分发
- 教师可选Creative Commons协议（CC BY等）开放共享
- 为什么这很重要：清晰的版权框架是大学采购的前提条件，也是平台规模化后避免纠纷的基础

## 六、路演加分项与避坑指南

### 6.1 加分项（Do These）

| 加分行为 | 效果 |
|---------|------|
| 开场用一个真实的"教师困境"小故事（30秒） | 比纯数据更有共鸣 |
| Demo中让评委看到"AI生成的脚本"的真实内容 | 眼见为实，比任何描述都有说服力 |
| 主动提到风险并展示缓释方案 | 展示成熟的商业思维 |
| 用"数据飞轮"这个概念做技术壁垒的核心叙事 | 评委对"飞轮效应"有天然好感 |
| 结束时留下一个具体的Ask（"寻找种子大学"） | 比"谢谢"更有行动力 |
| 准备一页Appendix: 架构图 | Q&A时如果被问技术细节可以翻到这页 |

### 6.2 避坑项（Don't Do These）

| 踩坑行为 | 后果 | 替代方案 |
|---------|------|---------|
| 说"我们没有竞争对手" | 评委直接扣分 | 说"赛道空白，但有潜在进入者" |
| Demo超时（>2分钟） | 压缩后面内容，节奏失控 | 严格计时，宁可少展示一个功能 |
| 用太多技术术语（Whisper、Lottie、Framer Motion） | 商业背景评委听不懂 | 说"语音识别技术""预制动画引擎""交互框架" |
| 展示未完成的界面 | 暴露不成熟感 | 只展示完成度最高的路径 |
| 路线图过于宏大（"改变全球教育"） | 显得不切实际 | 聚焦"6个月内验证20门真实课程" |
| 在Q&A中与评委争论 | 印象分大降 | 先承认合理性，再补充自己的思考 |
| 团队成员在台上互相打断 | 显得不专业 | 指定一个人主答，其他人补充 |

### 6.3 Q&A应答框架

对于任何评委问题，推荐使用**ACE框架**回答：

```
A - Acknowledge（认可）："这是一个很好的问题 / 您说得对..."
C - Core Answer（核心回答）：2-3句话直接回答
E - Evidence（证据支撑）：数据 / Demo / 案例佐证
```

**示例**：

> 评委："你们和洋葱学院有什么区别？"
>
> A："很好的问题，洋葱学院确实是我们的模式参照。"
>
> C："核心区别有两点：第一，我们面向大学，洋葱只做K12；第二，我们是AI自动生成，洋葱是人工精制。这意味着我们的边际成本几乎为零，而且教师可以自助生产。"
>
> E："从数据看，洋葱一节5分钟视频的制作成本估计在5000-10000元，而我们生成一节课的API成本大约5-10元，差了三个数量级。"
