# 证据、指标与对外表述边界

> 赛前状态：功能能力全部视为未实现。历史样例只能证明“材料里曾设计过什么”，不能证明本届参赛项目已经完成什么。

## 赛前 Claim Ledger

| 说法 | 当前状态 | 现有材料 | 赛前允许表达 |
|---|---|---|---|
| 教师可审核并发布内容 | 未实现 | 只有目标故事板和历史旧页面 | “我们计划现场验证……” |
| 学生可以答题并查看复习卡 | 未实现 | 只有结构设想和历史样例 | “目标闭环包含……” |
| 生成对象可回链口播或 PPT | 未实现 | 归档 `demo-pack/expected/` 有历史示例结构 | “我们准备验证这种数据结构……” |
| 新材料可实时解析和生成 | 未实现 | 无本届现场证据 | “现场 P1 目标是……” |
| 能降低教师审核时间 | 待测 | 无真实用户测试 | 只能说“希望验证是否降低” |
| 能提升学习效果 | 未验证 | 无对照实验 | 不作结果性声明 |
| 单课 API 成本 | 历史估算 | 归档 `demo-pack/metrics/` | 仅称历史估算，不作为本届结果 |
| 市场规模或商业效果 | 未核验 | 旧材料含二手信息 | 从核心路演移除或重新找一手来源 |
| 已形成数据壁垒 | 不成立 | 尚无真实规模数据 | 不使用该说法 |

## 赛前推荐表达

- “这是准备在 AdventureX 现场验证的产品命题。”
- “当前只完成了原始材料重构和现场任务设计，没有提前构建功能。”
- “历史样例帮助我们定义问题，但不作为本届已实现成果。”
- “我们想验证老师能否更快地审对并放心发布。”

## 赛前禁止表达

- “当前原型已支持……”；
- “我们已经完成教师审核或学生答题闭环”；
- “系统正确率达到某个百分比”；
- “制作成本降低 90%”或“显著提升学习效果”；
- “任何课程都能一键生成”；
- “已有数据飞轮或护城河”；
- 把归档旧页面或历史 PPT 称为本届现场成果。

## 现场证据记录模板

正式开赛后，每次真实运行至少保存：

1. 代码提交和功能完成时间；
2. 输入材料版本、权利状态与哈希；
3. 模型、提示词、参数或规则版本；
4. 生成对象、source IDs 与 schema 校验结果；
5. 教师通过、修改和移除记录；
6. 开始时间、结束时间与任务是否完成；
7. 失败原因、重试次数、成本与回退方式；
8. 测试人是否为团队成员，以及样本限制。

## 现场完成后才能更新的指标

- 来源正确性和来源覆盖率；
- 教师中位审核时长与接受率；
- 新材料冷启动成功率；
- 主要可用性卡点；
- 真实模型调用成本；
- 隐私、版权和删除流程是否落实。

任何指标都应保留分母、样本量、测量方法和限制，避免把小样本观察包装成普遍结论。
