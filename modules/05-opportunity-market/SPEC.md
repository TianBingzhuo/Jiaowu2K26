# Opportunity Market · 功能规格

> **功能 ID：** F-009 · **优先级：** P1 主链 + P2 Fixture 技术候选
> **基线日期：** 2026-07-21 · **技术验收：** 2026-07-24 · **状态：** `technical_review`

## 功能概述

把期刊、会议、竞赛、科研、实习、奖学金与校园活动做成来源透明、资格可解释、由本人控制资料的机会发现与双向匹配系统。发现页必须先区分 **校内机会 / Bear Down League** 与 **校外机会 / Open League**，再按类别细筛；UArizona 是当前校内品牌化示例，其他学校可替换赛区名称与来源适配器。明确禁止付费资格、随机资格、人员拍卖、自动投递和付费排名。

## 核心不变量

1. **完全透明：** 机会的所有信息（内容、资格、收益、义务、成本、风险）在打开前就可见；不用稀有度或等级遮蔽
2. **四态优于综合分：** 资格用"已满足/可能满足/未满足/未知"逐项解释，不汇总成单一百分比或分数
3. **本人控制资料：** 学生逐项选择用于匹配的资料；不用未授权的成绩、健康、家庭或财务信息
4. **不自动投递：** 正式申请必须由学生在权威系统主动操作；本平台只记录和镜像状态
5. **零付费操纵：** 排序不受付费影响、资格不可购买、机会不可随机分配、人员不可竞价
6. **来源可追溯：** 每条机会数据标注来源 URL、抓取时间和核对状态
7. **纠错渠道可见：** 每条机会提供明确的纠错/报告入口
8. **匹配可解释：** 每个匹配建议附带理由、冲突和未知项
9. **范围先于类别：** 校内活动与校外会议/赛事/雇主机会不混排；两区分别解释审批链、费用、差旅、外部规则与时效，不生成跨区“重要性总榜”

## 五种 2K 经济机制的安全转译

| 2K 机制 | 保留的抽象 | jiaowu2K26 实现 | 删除的伤害机制 |
|---------|-----------|----------------|---------------|
| VC | 有限资源与取舍 | Capacity：时间、精力、资助容量 | 付费买分/能力/资格/排名 |
| Card Pack | 主题化发现 | 完全透明机会包 | 付费随机、概率操纵、FOMO |
| Auction House | 搜索、供需、双方确认 | Opportunity Market | 给学生/导师/岗位竞价 |
| Paid Pass | 一段时间的权益集合 | Entitlement Wallet | 付费跳级、绕过先修/审批 |

## 资格四态定义

| 状态 | 含义 | 显示要求 |
|------|------|----------|
| `met` | 有证据支持满足此规则 | 绿色 + 证据来源 |
| `possibly_met` | 部分证据或需要确认 | 黄色 + 确认方式 |
| `not_met` | 有证据表明不满足 | 红色 + 下一步建议 |
| `unknown` | 缺少判断所需信息 | 灰色 + 如何获取信息 |

四态必须逐项显示，不能汇总成"你有 75% 资格"之类的综合分。

## 数据模型补充

### 机会范围枚举

| 范围 | 含义 | 必须额外说明 |
|---|---|---|
| `campus` | 学校、院系、实验室或校内组织管理的机会 | 校内资格、审批链、地点与校园服务边界 |
| `external` | 会议、赛事、基金会、雇主或校外组织提供的机会 | 费用、差旅、公开权利、外部规则与正式申请入口 |

### 机会类别枚举

| 类别 | 说明 | 典型资格规则 |
|------|------|-------------|
| `journal` | 学术期刊投稿 | 研究方向、导师推荐 |
| `conference` | 学术会议 | 论文摘要、注册费 |
| `competition` | 竞赛 | 年级、专业、团队规模 |
| `research` | 科研项目/实验室 | 先修课程、技能、时间 |
| `internship` | 实习 | 年级、专业、语言能力 |
| `scholarship` | 奖学金/项目资助 | 公开作品、用途预算、申请阶段 |
| `workshop` | 工作坊/培训 | 年级、兴趣 |
| `career_event` | 校内职业活动 | 在校身份、报名入口、时区 |
| `campus_event` | 校园活动/社团入口 | 校内身份、费用、容量、活动日期 |
| `campus_project` | 校园项目 | 技能、可用时间 |

## API 合同补充

### 错误响应规范

错误响应沿用全仓 `error-response.schema.json` 的扁平 `code / message / retryable` 结构。F-009 的 18 条路径以
`app/contracts/v1/openapi.yaml` 为事实源；反操纵技术验收入口为
`POST /api/v1/opportunity-fairness/run`，追加回放入口为
`GET /api/v1/opportunity-replay`。

审计检查项：
- 排序是否受任何付费因素影响
- 资格规则是否基于敏感属性产生差别
- 机会可见性是否因学生身份属性受限

## 安全与隐私要求

### 数据保护

- Profile 默认私密，只有学生本人可见
- 匹配使用的字段由学生逐项选择
- 不用未授权的成绩、健康、家庭或财务信息做匹配
- 匹配历史和保存的机会列表仅本人可见

### 公平性要求

- 排序算法不能基于姓名、性别、国籍、健康等敏感属性
- 定期检查推荐是否存在代理指标歧视
- 所有学生获得相同的机会发现能力
- 机会提供方不能按学生"价值"出价

### 纠错机制

- 每条机会提供"报告问题"入口
- 报告类型：过期、信息错误、不公平
- 过期机会自动标记 + 通知已保存的学生
- 资格规则改变后受影响匹配重新计算

## University OS 组合边界

- 学生“科研建议”由本模块负责机会、导师/团队、会议、基金和准备路线的来源透明匹配；F-004 提供课程/方向 What-if，F-006 提供本人私密能力证据。
- 教师科研路线由 F-013 Faculty Success Studio 负责，本模块只提供可复用的机会、资格、同意与公平匹配能力。
- F-011 General Balance 可展示已获资助、差旅/会议权益和用户预算，但资金不能购买机会排序、资格或学术优先级。
