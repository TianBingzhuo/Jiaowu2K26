# 智课工坊（SmartCourse Studio）项目演进路线

**项目代号**：SCS  
**定位**：面向大学及以上的"洋葱学院式"动画网课快速生成平台  
**核心闭环**：教师上传课程录音/课件 → AI生成洋葱学院风格动画讲解 → 学生观看 + AI实时出题  
**差异化壁垒**：① 大学课程深度 + ② AI实时出题 + ③ Computer use软件教学  
**文档版本**：v1.0  
**日期**：2026-06-23  

---

## 一、竞品分析（Porter五力 + 功能矩阵 + SWOT交叉策略）

### 1.1 竞争格局全景

本项目处于"教育内容生产工具"与"在线课程平台"的交叉地带，目前没有直接对标产品。最接近的参照系分为三类：

| 类别 | 代表产品 | 模式 | 与本项目的关系 |
|------|---------|------|--------------|
| K12动画课 | 洋葱学院、乐乐课堂 | 预制动画短片+练习 | 模式参照，但受众不同（K12 vs 大学） |
| 大学在线课 | 中国大学MOOC、学堂在线、Coursera | 录播长视频+作业 | 潜在替代品，但形式传统 |
| 知识短视频 | B站知识区、抖音知识号 | UGC短视频 | 注意力竞争者，非系统化课程 |

**竞争格局判断**：群雄混战中的"新兴市场"——大学动画课赛道尚无明显领导者，抢先教育市场、建立品牌认知是关键。

### 1.2 功能对比矩阵

| 功能维度 | 智课工坊（本项目） | 洋葱学院 | 中国大学MOOC | B站知识区 |
|---------|-------------------|---------|-------------|---------|
| 动画化讲解 | ✅ AI辅助生成 | ✅ 人工精制 | ❌ 录播 | ⚠️ UGC偶有 |
| 大学课程适配 | ✅ 核心定位 | ❌ 仅K12 | ✅ 但形式传统 | ⚠️ 不系统 |
| AI实时出题 | ✅ 独创 | ❌ 预制题库 | ❌ 无 | ❌ 无 |
| 教师自助生产 | ✅ 上传材料即生成 | ❌ 内部团队 | ⚠️ 上传录播 | ⚠️ 手工制作 |
| Computer use教学 | ✅ 独创 | ❌ 无 | ❌ 无 | ❌ 无 |
| 大学自定义 | ✅ 每校可配置 | ❌ 统一内容 | ⚠️ 有限定制 | ❌ 无 |
| 课程时长 | 5-8分钟/节 | 5-8分钟/节 | 30-60分钟/节 | 5-15分钟 |

### 1.3 SWOT分析

| | 正面 | 负面 |
|---|------|------|
| **内部** | **S（优势）**：AI出题+动画生成一体化闭环；Computer use教学差异化；教师门槛极低（上传材料即可） | **W（劣势）**：动画质量初期难达洋葱学院精制水准；品牌从零开始；技术栈复杂 |
| **外部** | **O（机会）**：大学网课完成率全球低于10%，形式改革需求强烈；AI工具降低内容生产成本；高校数字化转型政策窗口 | **T（威胁）**：洋葱学院可能向上延伸到大学；MOOC平台可能增加动画功能；AI生成内容质量不稳定 |

### 1.4 SWOT交叉策略

| 策略 | 行动方向 |
|------|---------|
| **SO（优势×机会）** | 用"AI动画+实时出题"双引擎抢先占据大学动画课空白市场，以教师自助生产模式快速铺量 |
| **WO（劣势×机会）** | 初期不追求动画精制水准，用"AI生成+人工微调"快速验证需求，动画质量随迭代提升 |
| **ST（优势×威胁）** | 用Computer use教学和大学定制化建立护城河，这两个功能竞品短期内难复制 |
| **WT（劣势×威胁）** | 先聚焦1-2个学科做到极致，避免全面铺开被竞品各个击破 |

### 1.5 Porter五力评估

| 竞争力量 | 强度 | 评估理由 |
|---------|------|---------|
| 新进入者威胁 | 中 | 技术门槛不高（LLM+前端动画），但"大学渠道+教师生态"是壁垒 |
| 替代品威胁 | 高 | MOOC录播课虽形式传统但免费且内容齐全，学生可能觉得"够用" |
| 供应商议价力 | 中 | LLM API（依赖大模型厂商）和ASR服务是关键输入，有多家可选但集中度高 |
| 买家议价力 | 中 | 大学采购决策链长但一旦合作粘性高；C端学生价格敏感 |
| 行业竞争强度 | 低（当前） | 赛道尚未形成，当前无直接竞争者 |

**综合判断**：行业整体吸引力中高。窗口期约12-18个月，需在竞品反应前建立渠道壁垒。

## 二、产品脑暴（SCAMPER + Impact/Effort矩阵）

### 2.1 HMW问题定义

**我们如何能让大学教师在不增加工作量的前提下，将现有课程录音/课件快速转化为洋葱学院级别的动画互动课程，让学生在5-8分钟内完成一个知识点的深度理解？**

### 2.2 SCAMPER七维度发散

| 视角 | 创意 | 描述 |
|------|------|------|
| **S-替换** | AI剧本生成替代人工编剧 | 用LLM将转写文本→结构化教学脚本，自动拆分知识点、生成讲解台词 |
| | 预制角色+模板替代从零动画 | 教师只选角色和模板，动画由系统自动渲染，不碰动画软件 |
| **C-组合** | 观看+出题+反馈一体化 | 视频每2-3分钟弹出AI生成的题目，答错自动推送针对性讲解片段 |
| | 转写+脚本+渲染一条龙pipeline | 教师上传一次材料，系统自动走完全流程 |
| **A-调整** | 洋葱节奏+大学深度 | 保持5-8分钟短片的节奏感，但内容密度提升到大学水平 |
| | B站弹幕→学习互动 | 借鉴弹幕形式，学生可在视频特定时间点标记"没看懂"，聚合反馈给教师 |
| **M-修改** | 缩小到极致：先只做1个学科 | 黑客松只做计算机科学/编程类课程，验证闭环后再扩展 |
| | 放大到极致：全学科覆盖 | 长期愿景覆盖理工/人文/医学等全学科 |
| **P-另作他用** | 考研/考证培训场景 | 同一套工具可服务考研辅导、职业证书培训 |
| | 企业培训场景 | 企业内训也可用，新员工入职培训视频化 |
| **E-消除** | 消除预制题库 | 全部AI实时生成，不维护题库，降低运营成本 |
| | 消除人工动画环节 | 教师不需要学动画软件，系统全自动 |
| **R-重排** | 先出题再讲解 | 颠覆"先看视频再做题"的传统流程，先测后学，AI根据薄弱点推送讲解 |
| | 学生数据→教师优化 | 学生观看/答题数据反馈给教师，指导下次课程优化 |

### 2.3 5Why根因追问

**痛点**：大学网课完成率低于10%

- **Why1**：因为视频太长太枯燥（30-60分钟录播）
  - **Why2**：因为教师不知道如何制作短小精悍的内容
    - **Why3**：因为缺乏低成本的内容生产工具
      - **Why4**：因为现有工具要么太专业（After Effects）要么太简单（PPT录屏）
        - **Why5（根因）**：大学教师缺少"从原始材料到动画课程"的低门槛转化通道
        - **方案**：构建"上传材料→自动生成动画课程"的一站式工具

### 2.4 反向脑暴

**问题反转**：如何让大学网课完成率更低？

| 恶化方案 | 逆转为改进方案 |
|---------|-------------|
| 视频做成60分钟不暂停 | 5-8分钟一个知识点，中间穿插互动 |
| 题目全是期末考试原题 | AI根据学习进度实时生成个性化题目 |
| 动画风格统一不变 | 不同学科可选不同视觉风格，教师可定制 |
| 学生看不到其他人进度 | 加入学习排行榜和社交激励 |
| 老师要学动画软件才能上传 | 上传录音/PPT即可，系统自动处理 |

### 2.6 黑客松MVP功能取舍结论

## 三、方案框架（MECE Issue Tree + 假设树 + Workstream设计）

### 3.1 Key Question

**智课工坊团队应如何在5天黑客松内构建一个可演示的MVP，验证"大学课程录音→AI动画讲解+实时出题"闭环的价值，并为后续孵化奠定技术基础？**

**项目范围**
- In-scope：录音转写→脚本生成→模板动画→AI出题→前端播放的完整闭环demo；Computer use教学的概念验证
- Out-of-scope：拖拽式代码测试模块、自研动画引擎、学习社交功能、B2C用户系统、支付系统

### 3.2 Issue Tree（MECE拆解）

```
如何构建可演示的MVP并验证核心价值？
├── 1. 内容输入层：如何将教师原始材料转化为结构化数据？
│   ├── 1.1 录音/视频转文字（ASR pipeline）
│   ├── 1.2 课件PPT内容提取（文本+图片+公式）
│   └── 1.3 课程结构化解析（知识点拆分、难度分级）
├── 2. 内容生成层：如何将结构化数据转化为动画课程内容？
│   ├── 2.1 教学脚本自动生成（LLM改写为洋葱风格）
│   ├── 2.2 动画素材匹配与渲染（预制角色+模板）
│   └── 2.3 配音与音乐生成（TTS + 背景音乐）
├── 3. 交互层：如何实现"观看+出题"的一体化体验？
│   ├── 3.1 AI实时出题引擎（根据脚本内容动态生成）
│   ├── 3.2 视频内嵌互动（时间节点触发题目弹出）
│   └── 3.3 Computer use教学演示（概念验证级）
├── 4. 平台层：如何让大学可以自定义配置？
│   ├── 4.1 大学信息配置（校名/院系/课程绑定）
│   ├── 4.2 课程管理与发布流程
│   └── 4.3 角色与权限（教师/学生/管理员）
└── 5. 演示层：如何在黑客松现场有效展示价值？
    ├── 5.1 端到端Demo流程设计与数据准备
    ├── 5.2 演示脚本与fallback方案
    └── 5.3 路演材料（PPT + 技术亮点）
```

**MECE检验**：
- 互斥：内容输入(1)≠内容生成(2)≠交互(3)≠平台(4)≠演示(5)，各层职责不重叠
- 穷尽：从"原材料进来"到"成品展示出去"覆盖完整链路，无遗漏

## 四、5天黑客松MVP计划（含并行/串行标注）

### 4.1 团队角色假设

假设4人团队，角色分工如下（可一人多角色）：
- **P1 全栈工程师**：负责后端API + pipeline编排
- **P2 前端工程师**：负责播放器 + 交互界面

- **P4 设计/产品**：负责动画模板 + UI设计 + 演示准备

### 4.2 五天排期总览

```
Day1: 基础搭建 + 并行启动各模块原型

Day3: 端到端整合 + 扩展功能原型
Day4: 打磨 + 演示数据准备
Day5: 路演准备 + 备选方案
```

## 七、PRD摘要（MVP版本）

### 7.1 背景与目标

大学网课完成率全球低于10%，核心原因是形式枯燥（30-60分钟录播）、无互动反馈。洋葱学院在K12验证了"5-8分钟动画+练习"模式的有效性，但大学层面无人做。AI工具（LLM+ASR+TTS）的成熟使"教师自助生成动画课程"首次成为可能。

**目标用户**：大学教师（内容生产者）+ 大学生（内容消费者）

**业务目标**：

| 目标 | 衡量指标 | 目标值 | 监测方式 |
|------|---------|--------|---------|
| 技术验证 | 核心闭环跑通 | 端到端可演示 | Demo走通 |
| 脚本质量 | 教学脚本可用率 | ≥70%无需大改 | 人工评审 |
| 市场验证 | 现场兴趣度 | 3+人主动询问 | 黑客松交流 |

## 八、技术选型建议（供开发参考，非PRD约束）

| 模块 | 推荐方案 | 黑客松理由 |
|------|---------|-----------|
| 前端 | Next.js + shadcn/ui + TailwindCSS + Framer Motion | shadcn/ui 5分钟搭建专业UI，Framer Motion做微交互 |
| 后端 | FastAPI (Python) | 与AI生态无缝衔接 |
| ASR | OpenAI Whisper / 阿里云ASR | 准确率高，有API |
| 脚本生成 | GPT-4 / Claude / DeepSeek | 长文本理解+结构化输出 |
| 出题引擎 | 同上LLM，不同prompt | 复用模型降低成本 |
| 动画渲染 | Lottie（预制角色）+ Framer Motion（微交互）+ HTML/CSS（场景） | 充分利用预制动画形象，黑客松最快出效果 |
| TTS | Edge-TTS (免费) / Azure TTS | Edge-TTS零成本，Azure质量更好 |
| BGM | 免版税音乐库（YouTube Audio Library等） | 零成本 |
| Computer use | PyAutoGUI + 录屏 / macOS原生自动化 | 快速原型 |
| 代码测试 | Monaco Editor + Pyodide(浏览器内Python) / Wandbox API | 学生直接在页面写代码运行 |
| 复习指南 | LLM + 考情工程方法论（详见独立规范文档） | 复用脚本生成prompt，零边际成本 |
| 数据库 | SQLite (黑客松) → PostgreSQL (孵化期) | 先简后繁 |
| UI增强 | Aceternity UI / Magic UI（可选） | 炫酷视觉效果，5分钟上手 |

## 九、版权与知识产权政策

### 9.1 教师原始材料

- **版权归属**：教师上传的课程录音、视频、课件PPT等原始材料的版权始终归教师所有
- **平台授权**：教师在平台发布课程，即默认授权平台拥有该课程内容的再分发权和用户下载/收看权
- **用户限制**：学生/用户只能在线观看和下载课程内容供个人学习使用，**不得将原始视频/内容再次分发**
- **开放协议选项**：教师可在平台上勾选 Creative Commons 协议（CC BY / CC BY-SA / CC BY-NC 等）或其他开源协议，允许用户按协议条款再分发和二次创作
- **未勾选开放协议时**：用户只能按平台默认权限使用（在线观看+下载，禁止再分发）

### 9.2 平台生成的动画课程

- **允许原样分发**：教师可将平台上已公开发布的动画课程，以**相同内容**在其他平台分发（如学校官网、LMS系统）
- **禁止二次创作**：未经授权，不得对平台生成的动画课程进行剪辑、配音替换、重新编排等二次创作
- **衍生权归属**：平台生成的动画课程（含脚本、动画序列、AI出题内容）的衍生权归平台所有，教师享有署名权和原样分发权

### 9.3 文字版复习指南

- 复习指南由平台AI引擎自动生成，属于平台衍生内容
- 教师可原样分发给本校学生
- 学生可将复习指南用于个人学习，不得商业化再分发

### 9.4 黑客松演示注意事项

在路演时明确说明版权框架，这既是专业性的体现，也是评委可能提问的点。建议准备一页"版权政策速览"图用于PPT展示。

## 十、数据飞轮效应（路演核心叙事）

这是路演时最值得强调的防御性壁垒——平台具有天然的数据正反馈循环：

```
更多教师使用 → 更多课程素材积累
        ↓
更多few-shot样本 → 脚本生成质量提升
        ↓
更好体验 → 更多学生使用 → 更多答题数据
        ↓
出题引擎学习优化 → 题目质量提升
        ↓
更高完成率 → 更多教师愿意使用（正循环）
```

**飞轮的具体机制**：

| 飞轮环节 | 输入数据 | 输出改进 | 壁垒效应 |
|---------|---------|---------|---------|
| 脚本生成 | 已有高质量脚本 | 新脚本的few-shot样本 | prompt积累越深，竞品越难追平 |
| 出题引擎 | 学生答题数据（正确率/区分度） | 题目难度自动校准 | 数据越多，题目越精准 |
| 动画模板 | 教师选择偏好数据 | 模板推荐和优化 | 使用数据驱动的模板库 |
| 自适应学习 | 学生观看+答题行为数据 | 个性化内容推送 | 数据壁垒最深的环节 |

**路演话术建议**："我们不是一个工具，是一个数据飞轮。每多一个老师用，下一个老师的课程就更好；每多一个学生答题，下一个学生的题目就更精准。这个正反馈循环是我们的核心壁垒。"

## 十一、黑客松UI/动画实战指南

调研了历届黑客松获奖项目的实现方式后，总结出以下结论：

### 11.1 黑客松高质量UI的实现方式

绝大多数黑客松项目并不是"从零设计"的，而是通过以下工具链快速搭建专业级UI：

| 工具 | 用途 | 上手时间 | 适用场景 |
|------|------|---------|---------|
| **shadcn/ui** | React组件库，一键添加高质量组件 | 5分钟 | 表单、卡片、对话框、导航 |
| **v0.dev** | Vercel的AI生成UI工具，用自然语言描述生成React组件 | 即时 | 快速生成页面布局和组件 |
| **Lovable** | AI驱动的全栈应用生成器 | 即时 | 快速生成完整应用原型 |
| **TailwindCSS** | 实用优先的CSS框架 | 10分钟 | 布局、间距、颜色、响应式 |
| **Aceternity UI** | 炫酷动画效果组件库 | 5分钟 | 渐变背景、粒子效果、卡片动画 |
| **Magic UI** | AI风格的UI组件和动画 | 5分钟 | 打字机效果、光晕效果、渐入动画 |

### 11.2 动画实现方案对比

| 方案 | 效果 | 上手难度 | 黑客松适用度 | 说明 |
|------|------|---------|-------------|------|
| **Framer Motion** | 专业级页面过渡和微交互 | 中（1-2小时） | ⭐⭐⭐⭐⭐ | React生态最强动画库，layout animations开箱即用 |
| **shadcn/ui + Tailwind** | 专业级静态UI | 低（10分钟） | ⭐⭐⭐⭐⭐ | 大多数黑客松项目的UI基底 |
| **Aceternity/Magic UI** | 炫酷视觉效果 | 低（5分钟） | ⭐⭐⭐⭐ | 适合做hero section和landing page |
| **Lottie** | 预制动画嵌入 | 低（复制JSON） | ⭐⭐⭐⭐ | 适合你的预制动画形象 |
| **Remotion** | React视频生成 | 高（1天学习） | ⭐⭐⭐ | 代码可控的视频渲染 |
| **Three.js/WebGL** | 3D效果 | 高（2-3天） | ⭐⭐ | 除非是核心卖点否则不建议 |
| **Phaser.js** | 2D游戏 | 中（半天） | ⭐⭐⭐ | 如果做小游戏demo |

### 11.3 推荐的黑客松技术栈

```
UI基底：Next.js + shadcn/ui + TailwindCSS
  ↓
微交互动画：Framer Motion（页面过渡、组件进出场）
  ↓
炫酷效果：Aceternity UI（hero section、landing page）
  ↓
课程动画：Lottie（预制角色动画）+ Framer Motion（文字/图表动画）
  ↓
代码编辑器：Monaco Editor（嵌入代码编辑+运行）
  ↓
播放器：video.js 或原生<video> + 自定义控件
```

### 11.4 你的预制动画形象的利用策略

既然你已有预制动画形象，建议按以下方式使用：

1. **确认格式**：如果是Lottie JSON格式，直接用Lottie React播放器嵌入；如果是PNG/SVG序列帧，用Framer Motion做帧动画；如果是Spine/DragonBones格式，导出为Lottie或CSS sprite
2. **模板化**：角色是固定的（预制形象），变化的是场景背景、文字气泡、道具和动画序列。每个"动画模板"= 固定角色 + 可变背景 + 可配置文字 + 动画时间轴
3. **脚本驱动**：LLM生成的教学脚本包含"场景描述""角色动作""文字气泡内容"等字段，前端根据这些字段自动组装动画序列

### 11.5 动画引擎路线图（修正版）

| 阶段 | 方案 | 理由 |
|------|------|------|
| 黑客松期 | Lottie（预制角色）+ Framer Motion（微交互）+ HTML/CSS（场景布局） | 最快出效果，充分利用预制素材 |
| Phase 1-2 | 升级到Remotion（React视频框架） | 代码可控、可模板化、输出真实视频文件 |
| Phase 3+ | 引入Blender Python API做半自动渲染管线（仅用于高质量3D场景） | 仅在融资后、需要3D动画时投入 |
| **永远不做** | **从零自研动画引擎** | Money Pit，ROI极低 |

## 十二、待确认事项

以下决策点需要你确认后才能最终锁定排期：

1. **团队规模与角色**：当前假设4人团队。如果人数不同，并行窗口需要调整

2. **学科聚焦**：建议黑客松只做计算机科学/编程入门这一门课的demo（因为拖拽代码测试模块在编程课场景价值最大）。是否同意？还是你想做其他学科？

3. **预制动画形象格式**（新增，关键）：
   - 你的预制动画形象是什么格式？Lottie JSON？PNG/SVG序列帧？Spine/DragonBones？
   - 这直接决定Day 1动画方案的技术选型
   - 如果是Lottie → 最佳，直接用Lottie React播放器
   - 如果是PNG/SVG → 用Framer Motion做帧动画
   - 如果不确定 → 先用HTML/CSS + Framer Motion做通用方案

4. **动画方案选择**（已更新，基于调研结论）：
   - 推荐方案：Lottie（预制角色）+ Framer Motion（微交互）+ HTML/CSS（场景布局）
   - 理由：充分利用你的预制动画形象，黑客松最快出效果
   - 可选增强：Aceternity UI / Magic UI 做hero section炫酷效果
   - 孵化期升级到Remotion（React视频框架）

5. **Computer use教学范围**：黑客松只做1个场景的概念验证（建议"Git操作"或"命令行入门"），是否合适？

6. **ASR方案**：你有现成的课程录音可以测试吗？如果有，需要提前准备好1-2段5-10分钟的录音

7. **LLM选择**：你有偏好的大模型API吗？（影响成本和效果）

8. **孵化时间线**：Phase 1的"3-5个大学种子用户"——你目前有大学渠道资源吗？还是需要从零开拓？
